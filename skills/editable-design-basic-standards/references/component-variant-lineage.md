# 组件族建模、恢复与变体血缘

本规则用于从共同结构识别业务组件族，并处理本地母组件丢失、同族组件数量异常和嵌套远程 Instance。共同结构指稳定的模块骨架、文字角色、内容槽位和布局责任，不要求每个实例的文案、素材、高度或原图层树相同。业务文案或操作结果不同不自动代表模块职责不同；也不能只凭外观相似就合并无关模块。本规则不授权修改远程组件库源文件。

按 [当前可见范围](visible-scope.md) 建模和审计实际使用的状态。母组件血缘、实例编辑同步仍验证；完整回读不包含未使用的隐藏状态或裁剪外细节。

## 先决定需要几个母组件

创建或恢复组件前，先为每组候选建立差异矩阵，至少记录：

- 共同模块职责、骨架和槽位；分别记录每个原模块的宽高、根边界和内容顺序，不把差异当成预先排除条件；
- 文案、图标/实例、可见性、状态样式和真实结构差异；
- 当前 `mainComponent` ID/key、母组件是否可解析、页面实例数量；
- 每项差异对应的 TEXT/BOOLEAN/INSTANCE_SWAP/VARIANT 属性、布局规则，以及预期组件族数、Component Set 数、Component/Variant 数；保留原结构须说明真实不适用或尚未完成的原因。

使用以下优先级决定组件数量：

1. 用户明确要求同类状态组成组件集时，建立一个 Component Set 和真实状态属性。状态内部的文案与可选区域仍用 TEXT/BOOLEAN，不为每条文案增加 Variant。
2. 没有独立状态要求时，标题、说明、数字及按钮文案不同，用一个 Component 的 TEXT 属性；已有嵌套按钮优先使用其自己的文字属性，外层无法暴露时保留安全嵌套覆盖。
3. 图片、插画、优惠券或内容区域的有无，用 BOOLEAN 属性；已有子组件的替换用 INSTANCE_SWAP。隐藏区域退出 Auto Layout 流，当前可见配置分别保持原画面。由显隐或换行形成的自然高度差不是拆族或新增尺寸 Variant 的理由。
4. 共同骨架可以包含“标题前图片”“标题与说明”“标题后内容”“库按钮”等可选槽位；先评估这类结构能否表达顺序差异。不要只因配图在上、优惠券在下，就拆成两个无关组件族。
5. 真实业务状态、固定规格或无法由可选槽位表达的布局差异使用 Variant，统一在一个 Component Set 中维护。不按所有内容显隐组合穷举变体。
6. 明确不共享模块职责与骨架的对象才记为不适用；同族已确认但无法无损实现或验证的候选保持 blocked/pending，不得用“内容不同”“高度不同”改为跳过。

### 课程报告的明确建模示例

- “体验课暂未解锁 / 本节课已开放”：一个「课程空状态」Component Set，两个 Variant：`状态=未解锁`、`状态=已开放`。标题、说明为 TEXT；插画复用原组件，辅助提示按状态显隐。它们是两个真实业务状态，不能只交付一个状态或两个没有归入集合的独立组件。计数为 1 个族、1 个组件集、2 个状态组件。
- “课程推荐 / 结课福利”：按「可选配图 + 标题与说明 + 可选福利内容 + 库按钮」识别同族，优先一个母组件。配图、优惠券等区域用 BOOLEAN，文案用 TEXT，按钮嵌套已有库实例。分别验证两种实际配置的顺序、原始高度、圆角和文字样式；确有不能由属性表达的状态样式时，在同族内补充明确状态建模，不能直接排除整卡。
- 已有库按钮不列为待新建本地母组件的候选，也不以新建按钮替代业务卡片的完成。若页面是手工按钮，先核验原始发布组件与可用覆盖；无法无损复用时记录依赖未完成，不创建局部按钮兜底。

“无法把嵌套子层暴露成外层组件属性”属于工具/API 限制，不会把纯文案差异变成状态差异，也不能作为创建多个 Component/Variant 的理由。

数字位数变化引发的 HUG 宽度变化不构成新 Variant；固定坐标导致的重叠也不是状态差异。发现此类问题时，先按 [字体、同族文字布局与间距修复](typography-layout-repair.md) 修复该族的共享布局，再判断真实组件差异。

## 丢失母组件与孤儿实例恢复

发现本地实例的 `mainComponent` 缺失、已移除或不再位于可追溯的文件结构中时：

1. 暂停逐个替换，先遍历目标范围内的全部 Instance，并按语义、结构签名、尺寸和视觉边界分组。
2. 为每组记录当前母组件状态、实例数量、差异字段和预期母组件数量；不得用显示名称作为唯一分组依据。
3. 每个同构组件族只选择一个未损坏、视觉完整的代表节点恢复母组件。其他同组节点必须迁移为该母组件的实例，不得从每个实例分别创建母组件。
4. 恢复前后逐实例保存父级、索引、坐标、尺寸、可见性、文字区间样式和嵌套 `mainComponent` key；替换后使用相同参数导出并比较。
5. 远程发布组件无法解析、key 失效或权限不足时，不得创建本地同名组件冒充发布资产；保留现状并报告。
6. 完成后确认孤儿实例、错误 `mainComponent`、零引用错误组件/组件集、历史替代节点和临时测试节点均为 0。

节点删除验证应以 Page/目标子树遍历、父级关系和移除状态为准；某些运行环境可能仍通过 `getNodeByIdAsync()` 返回已移除对象，不能仅凭“还能按 ID 取到”判定节点仍在画布中。

## 母组件根与背景边界

- 先选择真实承载卡片完整边界的 layout/background Frame 作为母组件根。若页面结构是“有背景填充的 layout Frame + 内容 Frame”，直接把该 layout 转为母组件；不要在它外面再套一层 Frame/Component，也不要让背景 Frame 继续作为页面孤立层。
- 母组件根负责背景填充、圆角和尺寸，内容层保持为根的直接子项。只有明确承担裁切、命中区、叠层或交互职责的包装层才保留；不能为了组件化新增无职责包装层；真实承载 Variant 身份与共享母实例的最小外层 Component 按下节分配职责，不作为冗余层清理。
- 组件抽取前先固定根边界、直接子项顺序和视觉尺寸；根结构不稳定时只报告，不通过外包组件或覆盖层强行修复。

## 共享基础组件与同步验收

组件集中的直接子项必须是 COMPONENT，普通 INSTANCE 不能直接充当 Variant。默认 Variant 不是其他 Variant 的父组件；克隆共同骨架也不会建立持续继承。需要共同维护的状态族，优先让各状态组件嵌套同一基础组件的可见实例，或共享职责明确的子组件。已有正确血缘时直接复用；不为统一形式给每个组件集强加整卡基础组件。

- 创建前记录 `sharedMasterId`、全部实际 Variant ID、各嵌套 Instance ID/mainComponent，以及共享字段、状态覆盖字段、页面内容覆盖和引用范围。只有文字差异仍优先单组件 TEXT 属性，不因此增建 Variant。
- 共享范围须明确：共用“标签内容”只保证其图标、文字、内部布局等未被覆盖的字段同步，不代表外层背景、圆角或 padding 也共享。状态色可留在外层 Variant；基础组件负责内容布局。确需整卡共享时由基础组件承载完整可视内容，外层仅负责 Variant 身份与布局适配，禁止双背景、重复圆角、隐藏母实例或叠加独立内容。
- 共享维护是该族目标时，只有同名层、统一属性接口或 Set 成员关系不算通过。若保留独立骨架，说明未共享的职责和原因；不能把它报告为共享母组件同步已完成。用户明确要求的共享关系无法实现时记 pending/blocked。
- 在可回退的最小样本中选择一个有代表性、未被实例覆盖的共享属性，例如共同布局 gap；保存实际原值与测试值。写入基础母组件后，另一次只读调用核实两个／所有本轮目标变体中的对应值、实际可见几何或效果，以及各状态差异和页面内容覆盖。涉及其他组件或授权范围外引用时不改共享源，先隔离最小样本；无法可靠隔离则报告阻塞。
- 恢复原值后再次独立回读，比较相同导出路径的原位 PNG、文字/样式/Paint/几何、组件关系和范围外保护。布局传播可能产生实例尺寸覆盖，须与写前 overrides 对照并仅清理实验新增项；不得清除用户已有覆盖。不能把写入调用自己的返回当作同步证据，也不能仅凭 mainComponent ID 一致推断同步。一次属性实验只证明该属性及声明范围；不宣称所有覆盖值都会同步。
- 保存 `shared-sync.json`：目标集合与基础组件 ID、共享/覆盖字段、测试属性和 before/test/restored 实值、各次调用和时间、每个变体的嵌套血缘、独立测试/恢复回读、图片比较、受影响引用与范围外保护结果。完整第三阶段审计引用此证据，并报告共享与非共享职责；现有审计脚本通过不替代同步行为验证。仅做小样本时独立交付该证据，不伪造全页审计通过或面板验收。

## 状态构建与受限路径修复

1. 先确定共同骨架、属性和真实状态，再选择实现路径；验收实际可复用行为与每个原画面，不把一种 API 创建顺序当成组件族定义。
2. 属性与布局可直接表达时，在本轮可编辑母组件上定义 TEXT/BOOLEAN/INSTANCE_SWAP；用 Auto Layout 和明确槽位承载显隐，创建真实实例验证当前配置与另一实际配置。
3. 需要 Component Set 时，先按“共享基础组件与同步验收”确定共享职责。仅需独立状态维护时，可从共同的本地组件骨架复制状态组件并只修改声明的状态字段；保留相同语义层名和属性接口，共同的可复用子块使用嵌套组件。所有状态归入同一集合，记录各页面实例到最终 Variant 的映射。Figma 同一组件集的兄弟变体不会自动同步内部结构，不能宣称仅因同属一个 Set 就已验证共享编辑同步。
4. 需要共享维护时，优先采用“基础组件实例 → 声明的状态覆盖 → 外层状态组件”的路径；基础组件独立于状态集合，验证内部母实例可见、血缘正确并完成真实同步测试。共享内容子组件已能满足职责时，不额外嵌套整卡母实例。
5. 遇到 `relative-transform`、子层尺寸或属性引用不可覆盖时，停止这条写法，检查残留并回到本地母组件/状态组件定义层处理布局。不得反复强写实例子层坐标，也不得把首次报错当作该族不能组件化的证明。确认母组件布局、可选槽位和真实状态定义路径仍不能无损实现后，才记录具体阻塞。
6. 不 detach 已有库实例，不隐藏整个母实例再叠原内容，不增加无职责包装层，不按文案复制多个母组件。只执行第三阶段时，不借建模修复原稿未授权的视觉缺陷或改变画面根边界。
7. `combineAsVariants()` 后重设预览位置与集合尺寸，并重新读取属性定义及当前 ID；每个实际状态都创建页面实例，验证文字属性、区域显隐、嵌套库按钮血缘、几何和像素。共用嵌套组件需验证母组件编辑同步；TEXT/BOOLEAN 需验证真实绑定，不能只有空属性名。

代表验证通过后才推广；同一组件族仍只保留最终母组件或组件集及实际使用的嵌套资产。完整证据和固定视觉门槛不因更换实现路径而降低。

## 实例属性的面板可用性验收

本轮新建或修改、且提供可配置属性的本地组件，不能仅凭属性定义存在、API 能赋值或现有实例画面正确，就宣称可配置。每个属性接口相同的组件族至少从最终母组件新建一个临时实例，通过 Figma 右侧面板操作该族实际暴露的 TEXT、BOOLEAN、INSTANCE_SWAP 或 VARIANT 属性，组合还原另一种实际使用的配置。核对显示内容、适用的长文案布局、样式保持及母组件同步；已有有效证据可复用，只补验缺失环节，不重复整套回归。

对本轮定义的 INSTANCE_SWAP，按该槽位在目标稿中实际使用且允许替换的资产配置 `preferredValues`，保留已验证且仍适用的首选项。每项保存真实 COMPONENT/COMPONENT_SET key，不用节点 ID、名称或猜测的 key 代替；不为补候选复制远程组件或改发布库源文件。独立回读母组件定义和新实例属性，再实际打开面板的实例选择器，确认预期候选可见、可选择，且替换后的内容、尺寸与血缘正确。仅看到“Created in this file”文件夹、能全局搜索或能通过 API 切换，均不能证明首选候选已可用；若业务明确要求开放选择且没有约定候选，记录该理由并验证实际选择路径，不强制填入无关资产。

**候选在建模前准备。** 同一文件已有面板验收通过、来源及样式仍有效的候选时，直接复用，不再从远程 key 重试，也不重复建候选。没有有效证据时，先在代表样本验证候选可解析，再推广母组件及页面实例；创建属性时即配置首选值和真实绑定，不留到交付后补齐。远程 key 能回读但面板不显示时，只做一次来源/可访问性核对；仍不可选，可用最小本地 Component 包含原远程 Instance，作为可选候选，保留远程血缘、尺寸、Paint/Style/变量与已有覆盖，不复制远程母组件或重绘路径。先比较该候选与原图标的画面和有效样式，再用其本地 key 验证面板可选；通过后复用这份映射。失败则记录具体阻塞，不重复尝试相同 key 或把大量资产搜索当成默认排查。

保存代表母组件/新实例 ID、属性名、预期配置、候选 key、API 回读与面板操作证据，并关联到该族的审计记录；验证后清理临时实例。工具或连接限制导致面板尚未验证时，记录该族 `pending`/`blocked` 和具体缺口，不得将技术写入或验证器通过表述为“可配置且已完成”，也不得向用户提供未经验证的操作指引。此检查由执行者主动完成，不等待用户试用后反馈。

## 嵌套远程 Instance 的属性降级

本地母组件可以保留远程组件库 Instance 作为内部结构，但 Figma 可能禁止把远程实例子层的文字或可见性引用为外层本地组件属性。遇到属性引用报错或属性不可写时，按以下顺序处理：

1. 保留远程 Instance，不调用 `detachInstance()`，记录其 `mainComponent.key`。
2. 若页面中的本地组件实例允许无损覆盖嵌套文字，加载真实字体后直接做实例文字覆盖，并验证文字样式、字色和文字区间样式仍正确。
3. 若差异只是显示隐藏，优先将 BOOLEAN 绑定到实际可选区域；允许区域隐藏后退出布局并使该配置达到原稿高度。逐一对照各原状态，而不是要求显隐切换前后高度相等；检查 Auto Layout、Grid、`SPACE_BETWEEN` 和约束，不能留下多余空白或引起非预期位移。
4. 若必须保留原布局边界，可评估透明度隐藏，但仅限非交互展示状态，且必须确认命中区、可访问语义和视觉导出均符合预期。透明度隐藏不是通用默认值。
5. 普通属性覆盖若不能保持预期视觉，则保留原节点并报告限制；已有明确修复授权和确定排版缺陷时，先判断排版修复路径是否适用，无需重复索要同一授权。不得解绑远程实例、复制多个文案组件或添加覆盖层伪造状态，也不得修改发布库源文件。

### 混合样式文字保护

直接修改实例文字前，先用 `getStyledTextSegments()` 或等价方式记录各文字区间的字体、字号、字重、行高、字距、字色和 Style ID。整体设置 `characters` 可能把混合字号或混合字体压平成单一样式，因此写入后必须按新字符范围恢复区间属性，再重新核对基线、宽高、换行和像素结果。无法稳定恢复时回退文字覆盖，合格的轻微字形边缘差异按 font-visual-policy.md 自动记录并继续，意外基线或排版变化仍须修复或回退。数字长度回归允许内容引起的 HUG 宽度变化，但须保持区间样式、基线规则和实际间距；恢复 Style 后再次验证，避免带回旧布局问题。

## 几何归一化

- 转成主组件后检查嵌套母实例的相对位置、尺寸和缩放；若母组件基准为零偏移，应将派生变体的对应嵌套实例归一化到同一基准后再排版。
- 写入子节点坐标前先读取父级 `layoutMode`。`GRID`、Auto Layout 或实例约束下，不能把直接设置 `x/y` 当作通用居中手段；应使用有效的布局属性，或在可控的 `NONE` 槽位中按实际边界计算位置。
- Figma 实例中的文字相对坐标通常不可直接覆盖。固定槽位文字应优先使用真实 TEXT 属性和母组件已有布局；若文案变更造成裁切、重叠或不可接受的几何差异，不要用解绑、覆盖文字、额外 Frame 或假定可写的 `x/y` 修补，回退该变体或在母组件上建立已验证的自适应布局后再派生。
- 同一组件族的共享几何必须显式检查：外层宽高、圆形图标槽位、内嵌按钮区域和变体间距。样式可不同，但不应因派生流程产生无意的尺寸差异。
- 同族文字须检查共享的真实字体、行高、字距、padding/gap 和基线规则；现有组件内部的显式奇数/小数间距同样进入修复。数字/分母/单位采用随内容增长的布局，不能要求不同位数仍使用相同分母 x；按排版修复参考测试短、中、长内容，并检查嵌套变体和全部页面实例是否残留固定尺寸覆盖。
- 需要显示 Component Set 边界时，同时检查 `strokes`、`strokeWeight` 和 `dashPattern`；不要仅凭名称或编辑器预览推断虚线存在。

## 必须验证的关系

- Component Set 的子节点都是预期数量的 `COMPONENT`，且变体命名/属性完整。
- 每个由母组件派生的变体，都能从其嵌套实例的 `mainComponent` 追溯到同一个母组件（若该嵌套实例按设计保留）。
- 采用嵌套母实例路径的变体中，母实例保持可见；采用共享骨架的兄弟状态组件则验证统一属性接口与实际嵌套资产，不虚构整卡母实例血缘。两种路径均不得出现“隐藏母组件 + 另建独立组件”或额外状态覆盖层。
- 预览实例分别指向最终 Component Set 中对应的变体，而不是历史副本或独立孤立组件。
- 已连接的远程组件实例仍保持原有 `mainComponent.key`；本规则不允许为了重建卡片而解绑它们。
- 对组件面板和预览使用相同截图参数检查边界、重叠、裁切、图标居中、变体高度和虚线；源页面仍与基线一致。

## 固定回归检查

每次采用本规则时，至少记录并核对：

1. 每个组件族的预期母组件数量等于实际数量；纯文案差异族只有一个 Component，没有文案 Variant。
2. 母组件根就是原 layout/background Frame，没有新增外层包装；背景填充、圆角和尺寸位于根节点。
3. 记录实际构建路径：实例派生时验证可见嵌套母实例及 mainComponent；共享骨架状态时验证同一 Component Set、统一属性角色及所有页面实例指向正确 Variant，不要求不存在的整卡嵌套关系。
4. 变体差异只落在已声明的 TEXT/BOOLEAN/INSTANCE/VARIANT 属性；没有 `detachInstance()`、隐藏整个母实例或独立覆盖层。
5. 页面中的每个重复节点都替换为最终 Component/Component Set 实例，实例实际显示的文案、图标可见性和颜色与目标状态一致。
6. 母组件内部原有远程 Instance 的 `mainComponent.key` 未变化；不存在为了暴露属性而复制出的独立文案组件。
7. 组件写入后独立回读本轮新建/修改的母组件、变体及全部受影响页面实例；包含第二阶段时更新文字排版与字色覆盖矩阵，只执行第三阶段时更新样式保持矩阵。未受影响族可复用有效记录，最终回读不能省略。
8. 孤儿实例、错误母组件指向、零引用错误组件/组件集、历史替代节点和临时测试节点均为 0。
9. 组件/组件集边界、变体尺寸和目标截图使用同一参数复核；组件抽取产生意外的文字槽位、裁切、重叠、背景边界或混合样式变化时，只回退该组件族。原有排版缺陷先修复并保存通过后的基线；不得因血缘有效就保留重叠或跳过内容长度回归。

本参考不改变组件候选阈值、样式映射、原位编辑策略或其他正常路径规则。
