# 基础结构快速路径

普通 UI 文字的轻微字形差异优先按 [字体与视觉容差](font-visual-policy.md) 自动验收并继续；本文旧的像素一致/失败表述不覆盖已通过该规则的变化。写入范围保护、明显排版、属性及非文字变化仍按原规则处理。

仅在预检发现图层命名或 Auto Layout/Grid 候选时读取。本参考的普通结构整理提升可编辑性和结构语义，前后截图像素一致；不做视觉美化或广泛层级重构。已确认的字体、固定坐标数量行或不合规间距须走 [排版修复路径](typography-layout-repair.md)，不能因为无法保留缺陷像素就直接跳过。

按 [当前可见范围](visible-scope.md) 过滤后预检；以下“每个”“全部”只指可见候选和影响其布局的最小依赖。隐藏/裁剪外内容不进入结构清理分母，不为命名或间距审计展开。

## 一次预检需要返回

- 源节点和结构阶段基线截图参数。
- 每个 Frame/Instance 的 `layoutMode`、尺寸、padding、gap、Grid tracks 和直接子项顺序。
- 直接子项的坐标、尺寸、`layoutPositioning`、Grid 位置、HUG/FILL/FIXED 和可见性。
- 泛化名称、错误语义名称、Group、疑似无职责包装层和布局溢出。
- 缺失字体、按钮组件 key 和结构阶段前的组件实例尺寸。

把候选分成“高置信无损整理”“转入排版修复”和“只报告”。没有前两类候选时跳过结构写入。排版修复通过后保存新基线，再执行本参考的无损整理。

## 高置信可写

### 1. 语义命名

只有从实际内容和容器职责可以确定含义时才重命名：

- `Section` → 具体区域，例如“主体内容｜商品”。
- `Container` → 具体职责，例如“套餐列表”“品牌与返回”。
- 非交互说明行误名为 `Button` → “服务项｜具体内容”。
- `Text`/`Icon` 包装层 → “价格组合”“服务图标底板”等真实职责。

不要改库组件内部图层名，不要仅依据节点类型或编号猜语义。名称修改不应改变任何视觉或布局属性。

### 2. 单子节点冗余包装层

仅当以下条件同时满足时才可清理包装层：

- 包装层只有一个子节点，且不承担 Fill、Stroke、Effect、Clip、Mask、命中区或交互职责。
- 子节点不是图片、装饰、角标或复杂价格组合的视觉承载层。
- 唯一子节点是 `TEXT` 时，如果包装层也没有独立的 padding、gap、文字属性或其他语义职责，应把仍然需要的尺寸/对齐责任转移到文字节点后删除包装层；父级为 `GRID` 时用 `setGridChildPosition(row, column)` 定位直接文字子项，不写只读的网格锚点字段。`COMPONENT`、`INSTANCE` 或承担真实文字布局职责的容器不适用此条。
- 唯一子节点是图标 `INSTANCE` 或单一图标向量时，只有在包装层不承担固定槽位、列宽、命中区或其他语义职责的情况下才可扁平化；若包装层用于保持固定图标槽位，则保留槽位、改用可控定位并按槽位边界将图标上下左右居中，不要为了删除一层而改变父级几何。
- 现有坐标能唯一反推出需要转移到父级的 padding、gap 或 itemSpacing，删除后子节点边界、顺序和可见性可保持不变。
- 清理后父级和子节点的显式间距为整数偶数，优先 4 的倍数；页面与组件内部一并检查。原有奇数/小数间距需改变像素才能归整时，先按排版修复路径处理并保存基线，不以“组件内部”豁免。

删除前记录包装层和父级的布局字段；写入时先补回父级布局责任，再删除包装层。视觉或布局边界发生变化时只回退该包装层清理项。

### 3. Auto Layout 子项被 Absolute 绕开

同时满足以下条件才修复：

- 父层已经声明为 HORIZONTAL 或 VERTICAL，但逻辑流式子项均为 `layoutPositioning="ABSOLUTE"`。
- 子项顺序明确，尺寸固定，坐标能唯一反推出四边 padding 和 itemSpacing。
- 切换为 AUTO 后，每个子项的 `x/y/width/height` 可保持原值。
- 没有重叠、角标、图片叠层、浮动控件或有意越界。

先记录父层和子项的全部布局字段，再设置父层 padding/gap，最后按顺序把子项改为 AUTO。写入后返回父层和全部子项 ID、写入前后边界和反推值。

### 4. 零宽 Grid 占位轨道

同时满足以下条件才修复：

- Grid 用 `0px` 或无意义轨道占位，中间控件另以 Absolute 放置。
- 现有控件位置能唯一反推出真实列宽，所有列之和加 padding/gap 等于父层尺寸。
- 将控件放入真实 Grid 后，全部直接子项边界保持不变。

创建真实轨道后，用子项顺序或 `setGridChildPosition()` 放入目标格，并显式设置 `gridChildHorizontalAlign` / `gridChildVerticalAlign`。第一次验证必须检查每个子项的 `x/y`，不能只检查列号。

## 只报告，不自动修复

- 根画布、背景、图片叠层、装饰柔光、角标、浮动返回入口和复杂价格组合；职责明确的数值/分母/单位行按排版修复路径处理，不因被命名为“价格”就跳过。
- 需要删除、合并、拆分或跨层重排的多子节点或视觉包装层结构（单子节点高置信例外见上文）。
- 无法唯一反推布局，且也不满足已确认排版缺陷修复条件的结构。
- 字体缺失且没有可靠的真实字体/降级方案。可可靠修复的字体问题先走排版修复路径，修正字体后重新测量，不能靠扩容掩盖。
- 主观间距、对齐、视觉层级、图片、图标、阴影和交互问题。

需要以上修复时切换到 `$analyze-page-generate-design`，或在交付中列为待处理项。

## 写入与像素门槛

1. 基础 Style/Component 联动完成后，获取结构阶段基线截图。
2. 在一次批量写入中处理高置信布局、语义命名和符合条件的单子节点包装层，并返回全部修改节点 ID。
3. 做结构审计：泛化命名、Absolute、布局溢出、组件 key、子项边界和源节点完整性。
4. 做结构审计：无职责空包装层为 0；页面及组件内部现有、新增和转移的显式 padding/gap/itemSpacing 为整数偶数，优先 4 的倍数；自然字宽与自动布局计算坐标不统一取整。
5. 用与基线相同的节点、尺寸和截图参数导出 PNG；优先比较解码后像素，编码稳定时可用文件 SHA-256/`cmp` 作为严格证据。
6. 普通无损整理结果不一致时，只定位、修正或回退对应结构项；不要重建整个目标稿。排版修复另外验证限定区域内改善、区域外像素一致，不与无损整理的基线混用。

## 已验证行为

2026-08-27 的独立测试中：泛化命名从 66 降为 0；两个套餐卡片由 Absolute 恢复为纵向 Auto Layout；页头由零宽占位列和 Absolute 中间控件改为真实三列 Grid；合理 Absolute 从 10 项保留为 7 项。结构前后 993×559 PNG 的 SHA-256 相同且 `cmp` 一致，购买按钮组件 key 未变化。该结果证明以上三类高置信操作可走快速路径，不代表其他结构模式也可自动修复。
