# 第三阶段的确定执行路径

只执行第三阶段时以本文件规定操作顺序、候选状态和验收方法；其他文件继续提供组件语义、可见范围、写入范围保护和布局要求。本文不授权第一、第二阶段，也不降低它们的验收要求。

## 1. 锁定运行与链接目标

- 用完整聊天 UUID 或新 UUID 作为 `runId`，写入任务目录和清单；原位编辑不改已有 Page 名称。不得用日期、源节点或 UUID 前八位作为唯一身份。只按保存的 Page ID 续跑，不能按同名 Page 猜测归属。
- 输入是 Page 时先读取顶层画面；不能对 Page 读取 Frame 专属几何或直接用整页截图代替每张画面的基线。使用 `scripts/collect_visible_scope.js`，保留裁剪外和隐藏内容。
- 默认 `editMode="in-place"`，直接编辑链接目标，保留根 ID、父级、位置与层级；范围外内容和共享母组件只读。按主文目标预检保存尺寸、裁切、滚动属性、顶层顺序、`baselineId` 和写前时间，不新建交付 Page。只有用户明确要求副本时才用 `safe-copy` 并保存源/副本映射。
- 原生 `exportAsync({format:"PNG",constraint:{type:"SCALE",value:1}})` 为像素比较的固定路径。`get_screenshot` 可用于预览，但不能和原生导出混作前后对比。原生导出失败先诊断一次；仍失败则阻塞该证据依赖，不重复同一调用。
- 每次只返回一份图片或有界分块，预先查看长度。`use_figma` 返回限制按当前工具报错/文档处理；大 PNG 的 base64 可按不超过 12000 字符分块读取，各块验证导出总长度和指纹相同后组装。不要在超限后反复返回整图。

## 2. 写前固定候选账本

保存 `inventory.json` 及其 SHA-256；组件写入后不能删除失败候选或改变其 `required` 值来缩小分母。后发现候选以新版本追加，并保留旧版和变更原因。

统计单位是语义组件族，不是任意嵌套母组件数。对每个可见的手工重复结构、状态差异候选逐项记录；已有实例另列血缘清单，不因“有母组件”自动判定其可复用行为已通过。背景和内容分离的同职责卡片仍须纳入分析。

按共同业务骨架归组，不能要求原子树、文案、素材或高度完全一致。候选记录共同槽位、差异到 TEXT/BOOLEAN/INSTANCE_SWAP/VARIANT 的映射，以及预期族数、组件集数和状态组件数；“一个族”可以包含一个组件集的多个状态组件。图片或内容显隐优先用属性；用户明确指定的状态集合必须列为待建 Component Set。已有库按钮列为复用依赖，不能变成本轮新建局部按钮的成果。详细判定见 [组件族建模](component-variant-lineage.md#先决定需要几个母组件)。

`families` 每项包含：

- `id`、`sourceNodeIds`：稳定族 ID 和原候选身份。
- `required`：确认为本轮需要处理的重复/状态候选时为 true。
- `rationale`：为何同族或不适用；无法确定的候选为 required=true、pending，不能静默排除。
- `initialDisposition`：`required`、`already-componentized`、`not-applicable` 或 `excluded-by-user`。后两者提供具体原因，用户排除另有原话证据。

候选最终状态只允许 `componentized`、`already-componentized`、`not-applicable`、`excluded-by-user`、`blocked`、`pending`。**required=true 的候选只有前两种状态可以完成**。字体、渲染、工具故障、失败回退和未验证不是不适用理由。已有组件计入已组件化前仍须验证本轮要求的血缘和行为。模型不得填写“跳过”来替代失败状态。

## 3. 代表实例门禁

先使用最小临时样本验证一个代表，再批量推广；不复制整页作为代表验证前置。使用原位完整渲染上下文；移出后必须先证明普通克隆的 PNG 与原位候选相同。流程：

1. 普通克隆对照：与基线解码像素一致。
2. 将克隆转为母组件，不重写文字/字体/样式；保存母组件对照。
3. 从母组件创建真正的实例，恢复父级、索引、尺寸、相对坐标、HUG/FILL/FIXED 等布局责任；验证**实例**的当前文案与画面。母组件一致不等于实例一致。
4. 只有第 3 项通过，才添加 TEXT/BOOLEAN/INSTANCE_SWAP 属性；每次绑定后复核。TEXT 属性保持一个母组件承载同族文案，不能用每条文案一个母组件代替。
5. 验证另一真实状态/文案、长文案和数字边界，保留本轮要求的母组件同步证据；按[实例属性的面板可用性验收](component-variant-lineage.md#实例属性的面板可用性验收)补齐实际替换候选，并从最终母组件新建实例完成面板操作验证。API 赋值成功不能替代该验证；通过后再推广。

需要状态组件集时，按组件建模参考确定共享与状态职责，需要共同维护的状态族优先复用共享基础组件或子组件，并完成“修改共享属性 → 独立回读各状态 → 恢复并复验”的同步实验；独立骨架复制不算共享同步。分别验证每个真实状态。实例子层位置不可覆盖时，先检查母组件/状态定义的布局与槽位；首次覆盖失败不等于组件族不适用。可选区域显隐须绑定真实节点，隐藏区域退出布局后与该配置的原稿比较；不要求不同配置的高度相等。不得用新增库按钮替代完整业务模块的候选完成。

如果第 3 项仅出现文字差异，先按 [字体与视觉容差](font-visual-policy.md) 使用 text-edge-v1 验收。合格时直接记录并继续第 4 项，不做字体文件追溯、往返改字或 SVG 诊断。只有超出固定规则或疑似明显排版缺陷时，才做一次有新假设的局部对照；不在正式目标节点上试错。

- PNG 字节不同先解码比较，不以压缩/元数据变化判失败。
- **同名同字重、相同几何、加载字体成功，均不能证明字形相同。**
- SVG 字形轮廓变化或 `text-regeneration-mismatch` 只是诊断信息，本身不是失败或暂停依据。按实际字体、几何和固定文字边缘规则判断；不能猜换字体、转曲/贴图、隐藏真实实例再叠原文字，或换基线掩盖变化。
- 原生编辑器是诊断对照，不是必然有效的修复。必要时在隔离样本中分别由原生界面和 API 创建真实实例，回读血缘，再在同一种导出路径内比较基线与实例。桌面端 PNG 与 MCP `exportAsync` 可能存在不同渲染结果，不得跨路径直接判定组件化有损。
- 两条创建路径都发生相同文字变化时，停止把问题归因为模型或某个创建命令。可只读比较字体文件版本、PostScript 名称及实际字形轮廓；同名不同版本、轮廓近似对应只能作为来源线索，不能宣称已证明工具加载了某个文件。停用、替换字体或重启字体服务属于环境变更，按当前用户授权范围处理；变更后必须重新做代表实验，不能直接改验收基线。
- 用户要求与团队库统一字体时，先核验真实 Text Style 的字体/字重与团队选定字体包的内部名称、版本和摘要。库内下载链接、样式名称、历史文字轮廓可能来自不同时间；不能自动把旧下载包当成当前统一版本，也不能只按文件名匹配 Medium/Semibold。若统一字体确实会改变历史字形，记录为用户授权的字体修正，独立验收后再建立组件化比较基线；不能将字体变化包装成无损第三阶段。
- 一个新假设对应一次对照；没有新证据不重试。同一触发点在代表上稳定复现后，暂停该依赖族，独立候选可继续。整页测试只在代表门禁通过后运行。

## 4. 固定视觉判定

第三阶段采用 [字体与视觉容差](font-visual-policy.md) 的固定 text-edge-v1。轻微字形差异记录为 warning/acceptedMinorTextDifference，不计 unexpectedPixelDifferences，也不把候选记为 blocked。文字轮廓之外的非预期变化仍按零差异保护；safe-copy 模式另验源稿及普通复制基线零差异。

不因 Figma 字体版本不可读、同事本机版本不同或 SVG 不同而中断；明显排版、文字属性、Paint 或非文字变化才走修复/回退。特殊字体和用户明确要求严格字形保持的文字不使用本容差。

## 5. 回退与收尾

回退优先恢复保留的原节点或只读克隆原结构，不手工近似重建。复查父级、索引、坐标、布局责任和像素；删除本轮临时节点并通过实际父子遍历确认。写入范围、边界或回退可信性失败为全局停止，候选自身失败仅阻塞该依赖路径。

独立候选继续按主文完成组件、属性、结构与命名审计。任何 required 候选 blocked/pending，最终只能 incomplete；局部成果可以保留，不能宣称整体完成。

## 6. 从证据计算验收

仍需主文的组件、属性、样式、边界审计；另运行证据门禁 `scripts/verify_component_evidence.py evidence.json`。最终 `validate_component_audit.py` 会重新读取证据门禁，并核对候选数量、受影响对象及根映射，不能只信模型填写的零值。

`evidence.json` 的结构与必要字段见脚本中的 `SCHEMA`。所有文件路径相对 evidence.json，文件引用为 `{"path":"...","sha256":"..."}`。保存：

- 写前 inventory 与最终 outcomes，族 ID 一一对应。
- 原位编辑：每张根只保存操作前/最终 PNG 一组比较，`role="final"`；`rootMappings` 兼容字段 `sourceId` 与 `copyId` 都填同一真实目标根 ID。before/after 快照带相同非空 `baselineId` 与递增 `capturedAt`（Unix 毫秒），程序逐像素比较。明确要求副本时：每张根保留源前/源后、源前/副本基线、副本基线/副本最终三种比较，sourceId 与 copyId 不同。新证据必须明确填写 `editMode`；省略仅兼容历史 safe-copy 记录。
- 独立回读的 before/after 快照及每个受影响对象的映射；`preserved` 保存实际需保持的文字、样式 key、字体、Paint、变量绑定、相对几何和布局字段，不能只填“unchanged”。有语义命名变化时不要将 name 放进 preserved，另附命名清单。
- 快照节点含 `kind=TEXT|LAYOUT|PAINT`。所有 kind 的 `preserved.geometry` 至少含实际 width/height；TEXT 另含 characters、fontName、fontSize、lineHeight、letterSpacing、textStyleId、fillStyleId、fills、boundVariables；LAYOUT 另含 layoutMode、clipsContent；PAINT 另含 fills、strokes、fillStyleId、strokeStyleId、boundVariables。混合文字追加真实 segments 逐区间数据，不能以 MIXED 字符串替代已知区间差异。现有 Style key 在可解析时同时保存。位置以相同渲染上下文归一化；母组件预览区的新位置不冒充页面实例位置保持。
- 组件母资产及所有受影响页面实例也进入 after 快照；映射可以一对多，但不可省略最终影响范围。真实文案/样式等应按各原节点对应，不用母组件默认文案替代实例原文。
- after 的 LAYOUT 节点记录实际 nodeType；after.componentAssets 为本轮新母组件/组件集逐项记录 {id,descendantIds:[实际可见后代 ID]}，这些后代全部进入 after.nodes 与 nodeMappings，不得遗漏母组件内部 Text。母组件预览区及其后代的映射标 role="master-preview"，此角色只免比较预览新位置的 geometry.rootX/rootY；仍比较实际文字/字体/样式/Paint、宽高和其他布局属性。页面实例不可标记为预览。
- 前后根边界包含 width、height、clipsContent、overflowDirection；原位模式另含 parentId、index、x、y，保留原父级、顺序和位置。程序按 editMode 检查每张根的完整比较覆盖；不为原位模式补造 source/baseline 图片。

程序能验证文件内容、像素、映射与计数的一致性；不能证明候选语义无遗漏或快照一定来自 Figma。最终仍须按真实调用记录检查读取来源、冻结时机及覆盖范围，不能把本脚本描述为自动证明一切。
