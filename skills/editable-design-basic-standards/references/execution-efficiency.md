# 执行效率与证据复用

用于组织读取、代表验证、失败处理和报告生成。遵循 [当前可见范围](visible-scope.md)，减少重复与返工；可见内容的组件血缘和质量门槛不变。

## 三阶段只扩展，不重做

- 第一阶段只建立写入范围保护、基础视觉属性、文字几何、显式间距和截图证据；不为后续阶段提前解析发布 key、搜索组件库、盘点组件族或读取深度结构。
- 用户显式跳过第一阶段并从第二阶段开始时，直接核验链接目标的写入范围与操作前基线，然后直接建立第二阶段全量台账；不执行或伪造第一阶段视觉修正与完成证据。只授权第二阶段时完成即停；第二、第三阶段同时授权时连续执行，并复用同一个目标和台账。
- 第二阶段复用同一目标稿；第一阶段已执行时复用其证据，只为全部可见文字/颜色补充 Style key、等价性和最小实例继承信息。第一阶段之后未受影响的字体、几何和范围证据不重复采集；跳过第一阶段时只复用目标预检产生的范围与截图证据。第二阶段没有按钮时不调用按钮替换。
- 用户显式只执行第三阶段时，直接核验链接目标的写入范围、根边界和操作前基线。随后直接建立组件候选、现有 lineage 与受影响 Style/字体/Paint 的前后快照；不读取历史第二阶段审计，不生成全量目标库覆盖矩阵，也不补做 Text/Paint Style 或发布按钮联动。
- “第二步+第三步”路径复用第二阶段已经验证的发布资产和覆盖矩阵，只对实际重复候选搜索等价组件并补充完整 lineage、属性、变体与深度结构。组件化写入会使受影响子树的第二阶段证据失效，因此只重新审计新增/受影响组件族，最后再做一次完整回读。“只执行第三步”路径同样只搜索实际候选所需的发布组件，组件化后更新受影响范围的样式保持证据，不扩大为第二阶段审计。
- 每个阶段结束后停止；但用户已同时明确授权多个连续阶段时，在前一阶段通过后直接进入后一阶段，不再等待中间确认。未获授权的后续阶段既不预执行，也不为其准备全量数据。用户回复“同意”后继续使用现有 Page、节点 ID、台账和基线，不重新创建副本。

## 读取一次，按依赖更新

- 字距采用“已有明确非零值保留，其余直接按 0”的快捷规则。复用已有预检，只在字体、字色和 Style 本来需要的批量读取中顺带取得字距，不先额外读完整页寻找非零值。字距 `MIXED`/缺失/未单独读取不触发逐字、逐区间、源样式追查、面板检查或临时探针；因其他属性必要的区间读取正常进行。最终必要回读顺带取得新明确值时按真实结果处理，仍未知则继续采用 0，不追加一轮字距核验。正常验收出现真实差异时只调查受影响范围。
- 台账以节点 ID/文字区间为索引，关联源节点、组件族、母组件与实例、发布资产、前后属性、证据及验证阶段。删除节点移出当前计数，历史记录保留；新节点必须实读，不能从旧节点照抄通过状态。
- 每轮影响范围包含直接修改节点、实际使用的嵌套变体与全部受影响可见实例在写入前后的可见范围并集；布局变化还包含必要父级和流式兄弟项的布局字段，不展开这些依赖的隐藏后代。母组件或变量的影响跨出授权范围时保持共享资产只读，使用安全实例覆盖或在第三阶段隔离最小组件依赖；不能通过复制整页跳过影响范围核验。依赖不明、外部编辑或读取结果矛盾时定向扩大回读，仍不能确认则保留对应候选；不得拿缓存推定未受影响，也不自动恢复整页隐藏内容深读。
- 同一发布 key、真实字体/绑定模式、布局与覆盖方式未变时，可复用对应的能力探测、编辑器证据和代表回归结果；正式新增实例的属性、实际边界与样式仍逐一回读。字体、组件定义、布局约束或相关覆盖改变时，使依赖的旧证据失效并重验；只改不影响渲染的名称/description 不重跑数字样本。
- 发布资产按本次实际需要验证；共享 Style 通过 ID/key 去重读取，节点引用逐一核对。Profile 的其他缓存映射无需每次全部导入；失效项按主流程重新发现，不更换目标库。

## 第一阶段合并执行

第一阶段在无错误、无外部编辑且依赖关系明确时，默认按以下三段完成；操作前后截图分别在只读预检与最终回读取得，不新增一轮重复审计：

1. 一次紧凑预检只返回目标边界与顶层顺序、可见文字和实际字体对、缺失字体、实际 Paint、非零圆角、按钮候选、显式间距、文字重叠/裁切及基础结构计数。Page 顶层只返回有序 ID 或紧凑摘要，不返回每个顶层节点的完整元数据；详细节点按下文体积预算分页。
2. 一次原位批量写入。先按预检结果加载实际字体，未验证的替代不写入；在链接目标范围内处理字体、实际 Paint、圆角、按钮视觉和显式间距，保留根 ID、父级、顺序与边界，返回全部创建与修改 ID。不增加 clone 或新 Page 前置。
3. 最后一次写入后只做一次独立全量回读：核对写入范围保护、目标前后结构计数、实际字体、Paint、圆角、显式间距、文字重叠/裁切和根边界；取得目标最终截图并与操作前基线比较，并运行边界验证器。没有新写入、失败或证据矛盾时直接交付。

最终回读必须在同一次调用中先按 `fontName` 和 `getStyledTextSegments()` 汇总目标真实使用的唯一字体对，逐一 `await figma.loadFontAsync()`，再读取 `hasMissingFont`。加载前的 `hasMissingFont=true` 只反映本次调用尚未加载该字体，不能直接计为文件缺失字体，也不能因此另开一次字体审计；字体对加载失败或加载后仍为 true 时才列为阻塞，并返回具体节点和字体对。

只有工具错误、返回截断、回读矛盾、外部编辑或最终回读后发生新写入时增加调用；补验只覆盖失效范围并记录增加原因。不得把字体、颜色、变量、样式绑定、圆角和间距拆成互不依赖的多轮第一阶段审计。

## 第二阶段合并执行

第二阶段在无错误、无外部编辑且依赖关系明确时采用以下合并路径；这是减少重复调用的默认组织方式，不是放宽验收：

1. 一次紧凑预检返回全部可见文字/区间、实际字体与排版、Text/Paint Style ID 与发布 key、可见非文字 Fill/Stroke、按钮候选、目标根边界和当前结构计数。相同 Style 只按 key 读取一次，节点引用仍逐项进入台账。
2. 使用 Profile 已知 key 时，在一次只读调用中批量导入本次实际需要的 Text/Paint Style 与按钮候选并读取真实属性。用户说明组件库已修复/重新发布时，先使历史 `MIXED`、旧版本 ID 和错误结论失效，再按原发布 key 做这次当前状态核验；正常后继续，不重复走旧探针。
3. 互不依赖的 Text/Paint Style 写入合并为一次调用，调用内逐项返回节点 ID、前后 key 与真实属性。按钮只有在候选等价性依赖样式写入结果时才拆到下一次写入；不等价则保留结构并记录原因。不要为每个节点、每个 Style 或每个字段单独发起调用。
4. 最后一次写入后只做一次独立全量回读和一次视觉校验；写入范围保护、全部文字/字色覆盖、按钮决定、结构计数和像素差异在这一次中完成，随后用同一份数据生成矩阵与最终审计。写入调用内的返回可用于即时失败保护，但不能替代这次最终独立回读。

仅在工具错误、结果截断、回读矛盾、外部编辑、未知依赖或最终回读后又发生写入时增加调用。补验只覆盖失效范围；没有这些触发条件时，不追加按钮探针、浏览器面板复核、多轮回读或重复截图。

## 分批返回，防止截断返工

节点清单与详细属性分开返回，每批带总数、当前范围和下一批位置。首次完整文字属性可从约 20 个区间一批开始，依实际返回上限调整；这只是批量起点，不是审计数量上限。遇到截断只缩小并补取失败范围，不反复请求同一大包，也不漏掉后续批次。

返回前按序列化后的体积限制批次，并给工具包装预留空间，不能只按节点数量切批。在已知约 20KB 上限的通道，正文先采用不超过约 12KB 的保守预算；其他通道按实际限制调整。单个节点仍过大时拆分字段或文字区间，保留节点 ID 与完整分页索引；不得截短属性值冒充完整证据。此前成功批次保留，只补缺失部分。

只返回当前阶段需要的字段；大型矢量路径、完整 Paint 等基线单独保存供精确比较，不在每轮文字审计中重复输出。写入返回全部创建/修改/删除 ID，量大时同样分批保全。独立只读请求可并行；依赖前一步结果的写入、回读与回退保持顺序。

## 先验证完整代表，再推广

在已确认可写的授权目标稿内完成每族代表验证；需要临时测试节点时纳入创建/删除台账。验证完整的“创建母组件 → 创建页面实例 → 属性覆盖 → 独立回读”路径；确有变体时，还须在创建页面实例前完成实际状态派生与组件集组合。覆盖该族实际画面已显示或用户明确要求的状态与可见布局约束，纯文案族仍只建一个组件，不能只测试一次 API 是否成功。

按主流程验证真实样式、血缘、几何、图片/矢量边界与像素；数字行在此批量跑完当前、短、中、长内容。共享实现与约束未变时，批量替换后可复用这份数字样本结果，但必须检查全部新实例的实际布局及局部覆盖；存在不同约束的实例另做回归。最终仍执行全范围属性审计和规定的像素检查。

## 失败要改变方法，不能重复碰运气

浏览器或桌面端每次打开文件、跳转节点、切换选择后，先确认目标文件/节点已到位、加载提示消失、所需属性面板已显示，再正式读取；导航调用返回不代表 Figma 已就绪。优先使用当前工具支持的条件等待，否则有界检查就绪状态，不连续抓取完整页面来碰运气。等待超时后保留加载/错误状态并诊断，不把空面板计作一次有效属性读取，也不因尚未加载完成就切换浏览器和桌面端重做。

失败后记录错误、残留节点和实际前后值，再按原因处理：参数错误依据当前对象类型/API 修正；返回截断缩小批次；页面未就绪则按上述条件等待。加载中的空面板不能证明节点或字体缺失。

相同方法已被证实无效且前提未变时，不换一段等价代码继续试。写入未报错但独立回读未改变，亦视为失败。只有新证据支持不同方案或环境已变化时重试；同一外部原因连续两次失败仍按主流程停止该路径。无法保持质量的候选如实报告未完成，不跳过门槛。

曾遇到的兼容性问题只在当前环境出现对应现象时采用，不当作 Figma 永久限制：

- `combineAsVariants()` 后组件属性 ID 可能变化：从最终组件集重新读取定义，按属性名和类型解析当前 ID；名称歧义时先消歧，不能沿用组合前的 ID。
- 转成 Component 后 HUG/AUTO 可能变成固定尺寸：代表验证时回读根、嵌套实例及内容层的 sizing、min/max 和实际宽高，确认后再推广。
- 嵌套子层的位置、尺寸或属性引用不可覆盖：先检查现有属性、主组件布局和可选内容槽位；按组件建模参考在本轮本地母组件或真实状态组件定义层实现，不强制从实例派生所有变体。只有显隐或内容长度差异时仍优先单母组件属性，不因接口限制增加纯文案 Variant；不 detach 库实例，不隐藏整卡母实例或使用覆盖层。不能仅改一个 width 字段或一次坐标覆盖失败就判断整族成功或无法实现。
- 宋体字体名称或字重在接口不可用：按[宋体必须使用思源宋体](typography-layout-repair.md#宋体必须使用思源宋体)核验可用的同字重思源宋体；例如 `Source Han Serif SC / Heavy` 不可用时检查 `Source Han Serif CN / Heavy`。同字重思源宋体仍不可用则报告阻塞，禁止降级为 PingFang。相同环境复用已确认的字体加载结果；其他字体的编辑器/接口差异分别留证，不以错误字重凑成功。

## 一份台账生成交付

中间阶段只更新台账、证据和必要基线；包含第二阶段的路径从台账计算两份覆盖矩阵及进度计数，只执行第三阶段的路径从台账计算组件候选覆盖、lineage 和受影响样式保持矩阵，不手工维护多份汇总。最后一次写入与临时节点清理之后，独立全量回读授权交付范围，刷新全部当前记录，再从同一最终数据用对应脚本生成审计 JSON、矩阵、资产清单和交付报告。报告引用已有截图和回归证据，不为排版报告重复采集 Figma 数据。

最终门禁通过后无新写入、失败或矛盾时直接交付。若又修改 Figma，相关验证失效，须补验并重新生成最终结果；不能使用旧的通过报告。

失败重试时记录调用类型和结果，方便区分正常制作与返工。除非用户主动询问，交付不输出或估算端到端耗时、工具耗时、分项耗时或节省时间；即使用户询问，也只报告可证实的数据，不把工具执行时间冒充完整阶段时间。
