# 当前可见范围

本参考统一三个阶段的读取、处理和验收口径。默认 `current-visible`，以每个实际画面根节点的原始边界及当前祖先裁剪交集为准，不以编辑器窗口、缩放或图层面板是否折叠为准。用户明确要求展开、滚动后的内容或其他状态时，才把相应状态作为额外验收范围；不默认展开整棵组件树。

## 先过滤，再读取详细属性

- 先读可见性、实际渲染边界、裁剪和必要布局关系。节点或祖先 `visible=false` 时跳过该子树，不读取其字体、Paint、Style、组件定义或后代数量。
- 完全在有效裁剪区外且确认不会绘制回可见区域的子树，跳过详细读取。非裁剪父层在屏外不代表后代在屏外；保留必要的子层边界探测。部分可见节点仍纳入，不能因为只有少量像素可见而排除。
- 判断边界要包含阴影、描边和溢出。遮罩、旋转、混合效果或边界不可用时采取保守纳入，不用未经证明的矩形相交判断排除内容。无需计算所有重叠层的逐像素遮挡。
- 保留影响可见内容的最小依赖：祖先裁剪和背景、Auto Layout/Grid 的尺寸/间距/顺序、约束、参与布局的兄弟项，以及实际复用的母组件属性。依赖节点只读取相关字段，不因此展开它的全部文字和隐藏后代。透明节点仍可能占据布局空间。
- 可复用 `scripts/collect_visible_scope.js` 收集详细读取节点和布局依赖；它是保守候选过滤器，不代替实际布局、遮罩判断和最终截图。不能先 `findAll()` 全量展开、读取完整属性后再过滤。剔除数量只记录遍历遇到的子树边界数量，不为统计跳过的后代补做全量遍历。

## 处理与保留

只对可见内容执行当前阶段授权的样式、组件和结构处理。隐藏/裁剪外内容原位保留，不主动删除、展开、改名、重绑样式或修复其几何。组件化可能连同完整内部结构复制；这不要求审计其隐藏细节，也不承诺减少复制或截图工具本身的耗时。

局部母组件仅按本次实际使用状态对应的可见范围检查；必要时通过真实页面实例映射母层，不能因母组件放进预览区后露出更多内容而扩大范围。血缘、可编辑性、可见内容的母组件同步、根边界及本次临时节点清理仍需验证。所有实际画面中已显示的同族状态都要覆盖，不检查未使用的隐藏状态。

写入前后按可见范围的并集复核，防止误隐藏原内容或漏掉新露出的内容。改变可见布局时重新确认最小依赖；不明依赖先定向扩大检查，仍无法判断则保留该候选，不退回默认整页全量深读。

## 验收与计数

正文及其他参考中的“全量”“全部子树”“完整回读”均表示本次声明的可见范围和最小依赖，不覆盖已排除的隐藏/裁剪外细节。文字/颜色覆盖、候选分母、缺陷与几何回归均按此口径；排除项不计为 `exception`、`skippedWithReason` 或未完成项。依赖检查用于证明可见结果，依赖中的无关文字不进入样式覆盖分母。

根宽高、裁剪和滚动属性不变；可见像素、排版、Style/字体/Paint、母组件同步仍按原有门槛验收。使用相同父背景、裁剪和导出参数比较，半透明模块优先在原页面上下文中比较整屏。仅在不可见范围且不影响可见布局的数值差异不计入 `geometryRegressions`，但可见回归或未知依赖不能改名为裁剪外差异。不要为排除项采集全文哈希或逐层前后快照；写入范围保护采用链接目标 ID、写入节点范围、根前后边界和必要的可见证据，已有可信保护记录可复用。

新生成的审计 JSON 增加以下 `scope`；第一阶段无审计 JSON 时，在交付记录中采用同一口径：

```json
{
  "scope": {
    "mode": "current-visible",
    "processingRootIds": ["3:4"],
    "dependencyCheckPassed": true,
    "excludedContentPreserved": true
  }
}
```

`processingRootIds` 是实际编辑的画面根节点；明细中记录状态/裁剪范围和必要依赖。两个布尔值须有真实读取、写入范围和视觉证据，不能仅为过门禁填 true。任一为 false，阶段为 incomplete。用户明确要求扩大范围时，`mode` 使用 `explicit-expanded`，并增加非空 `requestedScope` 说明具体范围，沿用该范围的完整门槛。

两个审计验证器检查上述声明，仍保留现有像素、样式、血缘等门槛；脚本无法自行判断节点是否可见。无 `scope` 的历史 JSON 按旧逻辑验证，不能自动重解释或清零过去的失败项。交付注明“当前可见范围已完成”；不声称隐藏内容、未展开报告或未请求状态也已完成。
