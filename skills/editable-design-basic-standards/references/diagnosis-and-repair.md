# 失败必须定位到可验证原因

普通 UI 文字的轻微字形差异优先按 [字体与视觉容差](font-visual-policy.md) 自动验收并继续；本文旧的像素一致/失败表述不覆盖已通过该规则的变化。写入范围保护、明显排版、属性及非文字变化仍按原规则处理。

本文件补充 A-r2 的执行方法，不降低三阶段验收门槛。遇到问题按以下顺序查证，不把首次失败直接改成跳过。

## 字体别名与运行环境

1. 区分源设计真实字体、HTML/CSS 导入别名、桌面端可用字体和 MCP 可加载字体。`hasMissingFont`、加载错误及字体名称不是同一个证据。
2. 对导入别名，查对应源 CSS 的 `@font-face`、实际字体文件 name 表及 OS/2 字重，保存路径和摘要。不能只凭“像苹方”猜测。CSS weight、导入节点 weight、字体文件真实 weight 分开记录。
3. 找到唯一对应的原字体时，恢复为同一字体文件声明的 family/style，属于导入映射修复；特殊字体仍保留其真实字形、字号和用途。没有可靠来源时不得换成其他字体。
4. MCP 无法加载原别名时，先检查 Figma 桌面端当前目标页的 Missing fonts。本页替换前核验页面、数量、各 style 和作用范围；禁止使用整个文件替换，以免修改范围外节点和历史测试。
5. 桌面端修复后，重新读取真实字体、字重、几何和截图，并单独测试 MCP 加载。桌面可用而 MCP 不可用时，不能声称 MCP 编辑能力通过；可在原生编辑器完成确有必要的操作，再回读验证。

### 原生文字编辑的定位与提交

此路径只在 API 无法完成必要编辑、原生编辑器确实可用时采用。

- 写前按节点 ID 保存原文与受保护排版属性，同时保存目标 Page 的顶层节点 ID 清单。字体或颜色操作的文案预期值就是原文；恢复历史误改时，使用误改前快照中的原文，不能拿已损坏的当前值作基线。
- 搜索结果仅用于定位。设置为当前目标页搜索，选中结果后核对文件、页面、链接中的节点 ID 和单一 Text 类型；结果数量、显示名称或排序不能替代身份核对。
- 单个文案修复须分开验证“选中节点”和“进入该节点文字编辑”。先进入编辑并观察当前焦点/光标，确认后才选择文字和粘贴；不得把 Enter、全选、粘贴串成无中间观察的操作，也不得在多选、画布或搜索框焦点下粘贴。更改字体或颜色只操作对应属性控件，不能通过粘贴相同文本给多个标题来触发更新。
- 每次原生文案修复后退出编辑，独立回读该 ID 的 characters、字体、字号、行高、字距、样式与几何，确认未新增页顶层文字。这个回读必须通过，才处理下一个目标；不能以截图看似正确代替节点内容。
- 若出现额外节点或另一标题变化，停止后续批量操作，记录新增 ID 和被误改 ID。仅依据写前清单恢复本次误改、清理能确认由本次操作产生的节点；不要清理来源不明的既有文字。恢复后重验所有本次受保护文字和顶层节点差集。
- 原生端存在未同步修改时，不刷新或重启来强制同步。先恢复连接，并核对原生端与 API 的同一目标 ID、文案和结构是否一致，再继续跨工具写入。缺少独立回读能力时，修复保持待验证，不能宣称保存或通过。

## 像素比较保持上下文

1. 探针必须保留绝对坐标的小数部分、祖先裁剪、父级布局、缩放、效果和导出参数。把 Text 单独移到画布另一位置，不是有效的同条件对照。
2. 优先使用最小但完整的临时渲染上下文验证，不自动复制完整页面。先验证无写入基线一致，再测试单一变化，最后验证真实界面根。
3. PNG 字节相同可以证明像素相同；字节不同必须解码为 RGBA 后比较尺寸和像素，不能直接认定视觉回归。PNG 元数据或编码差异不是画面差异。
4. 字节或像素真实变化时，记录差异区域、具体属性及失败阶段；基线失配先修比较条件，再决定写入是否失败。不得用容差掩盖未经解释的变化。
5. 拆除独立背景并把 Fill 合并进 Auto Layout 内容框时，核对两者的绝对位置、小数坐标和实际渲染边界。内容框的 HUG 宽度、对齐、内边距变化会改变背景的最终位置；`cornerRadius` 从原值改为胶囊圆角也属于视觉修复，不能算纯结构无损整理。边界外只有一列或少量像素仍是失败；先定位到具体背景/内容框，再在原冻结区域内修复并复测，不能事后扩张区域取得通过。

## 共享依赖的局部修复

共享母组件只读，不代表其所有实例内部都必须跳过。若普通业务组件的内部结构需要改变，复制可解析的本地母组件到本轮组件区，保留实例覆盖与嵌套发布组件，验证后仅迁移本轮实例。不得改写原母组件、解绑远程组件或以多个文案母组件替代 TEXT 属性。

### 内容长度与实例覆盖的真实回读

- 数字回归同时检查左边界、右边界、相邻单位/货币符号和后续内容；右侧没有溢出，不能证明右对齐或居中文字没有向左覆盖相邻元素。进度行还须检查轨道和可见进度填充的实际宽度及比例。
- 对嵌套实例执行 `resize()`、换组件或设置属性后，独立回读最终页面实例的实际几何。调用无报错不等于覆盖已生效；组合组件集或再次实例化后也可能恢复主组件尺寸。不能只验证母组件或颜色正确。
- 尺寸覆盖不能保持时，回到本页共享母组件建模。真实状态可由现有可见性属性或可交换子实例表达；各状态仍须保留同一母结构血缘，且只有预期状态可见。不得以隐藏整个母实例、另放覆盖层来伪造通过。
- 隐藏子层可能不出现在工具返回的 `children` 中。验证图标或状态开关时按节点身份、类型与 `mainComponent` 定位，不能用固定数组下标读取另一个可见节点并当作隐藏状态证据。
- 卡片内部不溢出之后，继续检查外层固定画板的裁剪和滚动责任。长文案导致卡片增高时，不能只用内部布局通过替代外层可达性验证，也不能扩大截图范围掩盖裁切；保留源根节点的尺寸、裁剪和 overflowDirection；原稿静态视口之外的压力测试内容记录为视口限制，不以内部组件通过宣称已验证整页滚动可达性。只有用户明确授权改变交互配置时才可调整滚动，并单独验证。

### 替换和回退必须恢复布局责任

- 保存原父级、索引、相对坐标、尺寸、`layoutPositioning`、HUG/FILL/FIXED、最小尺寸及约束。父级为 `NONE` 的原位替换和回退都必须显式恢复 `x/y`；只插回原父级不会自动恢复旧坐标。
- 切换 Auto Layout 可能经过中间尺寸，令绝对背景的 STRETCH 边距发生变化。完整布局稳定后再核对背景的四边、宽高和实际实例，不能只核对内容。
- 修改文字对齐可能改变少量字形边缘。仅为适配容器时，优先保留原始对齐和字体参数，由父级布局处理定位，并以相同渲染条件复核。

## 继续与完成

每个失败保留：症状、已排除原因、根因证据、修复动作、复测结果。独立候选可以继续；仍有必要工作失败则整体不能 complete。第一阶段修复造成的预期字形/排版变化与后续组件化无损比较使用不同基线，不能借换基线掩盖未经验证的改动。

### 非文字颜色的完整扫描

普通颜色预检须同时读取 Fill 和 Stroke，不能因为旧脚本只枚举 fills 就漏掉功能图标描边。半透明、图片、插画与特殊装饰保留策略不变。发现可归一化的描边时，先记录原 Paint、用途、色差和所有可见实例的图标影响区，再修正授权目标稿内的实际颜色；第二阶段再绑定发布样式。新的修复区属于独立前置计划，不得回填旧失败对比来掩盖区域外变化。
