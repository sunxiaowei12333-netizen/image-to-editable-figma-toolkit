# 字体、同族文字布局与间距修复

普通 UI 文字的轻微字形差异优先按 [字体与视觉容差](font-visual-policy.md) 自动验收并继续；本文旧的像素一致/失败表述不覆盖已通过该规则的变化。写入范围保护、明显排版、属性及非文字变化仍按原规则处理。

出现正文偏细/字体不符、固定坐标数字行、同族文字错位、内容变长重叠、奇数/小数显式间距、排版属性读取异常或文字样式失链时读取。本路径先诊断，再修复授权目标稿及其本地组件中的确定缺陷，不修改远程组件库、共享资产或授权范围外实例，不做主观重设计。

## 1. 先确定缺陷和影响范围

一次预检记录受影响节点、所属组件族、可见截图、实际字体/样式/变量、布局字段和子项边界。分清两类操作：

| 操作 | 基线与验收 |
| --- | --- |
| 普通联动、组件抽取、无损结构整理 | 操作前后像素一致，原有缺陷另行进入修复台账 |
| 已确认字体、数量行或间距缺陷修复 | 写入前限定修复节点、目标和影响区域；修复区域内核对实际改善，区域外像素一致 |

影响区域要包含可预期的流式排版位移，但不能把整页随意圈为修复区。实际影响超出预估时先停止并定位，不能事后扩大区域掩盖误改。修复通过后保存新基线，再做组件抽取的无损比较；初始基线作为历史证据保留，不能用修复后基线覆盖。

用户已要求规范化/修复时，可在授权目标稿内直接处理有证据的缺陷。用户明确要求逐像素保留或禁止改间距时，遵守该限制并报告冲突；主观判断或范围外改动不能借此自动获授权。

修改已有母组件前追踪其嵌套变体和关联实例。若会影响范围外节点，先在授权目标稿内建立真实的本地组件血缘并迁移目标实例；不可为修复目标节点直接改共享源母组件或发布库。不解绑远程实例，不用隐藏母实例、覆盖文字或独立文案组件伪造结果。

### 文字样式链接保护

**读取异常不是已确认缺陷，也不是永久阻塞条件。** 已有数据或正常预检顺带返回的明确非零字距保留，其余直接采用 0；不先额外遍历全部文字来寻找非零值。仅字距为 `figma.mixed` 时不触发 `getStyledTextSegments()` 或逐字符读取。因混合字体、字色或样式等其他必要属性已需读取区间时，顺带保留明确的字距和分段差异；其他未知属性按以下规则核验。记录已有原始值和读取对象，未单独读取就如实标记，不为补齐字距记录增加调用。

#### 组件库修复或重新发布后的重新核验

- 用户说明组件库已修复、重新发布或更新文字样式后，旧节点中保留的 Style 版本 ID、历史 `MIXED` 和此前的库错误结论不再作为当前证据。先按同一个发布 key 批量重新导入本次需要的 Text Style，核对 key、类型、名称、真实字体、字号、行高、字距及其他排版属性。
- 当前导入样式已明确返回目标值时，把它作为正常发布样式处理：在一次批量写入中重新绑定受影响文字，保持文字中心/布局职责，最后通过一次独立全量回读和一次视觉校验确认 key、真实属性、尺寸、换行、重叠与裁切。不要因为旧节点仍引用旧版本 ID 或旧读取曾为 `MIXED` 而重建探针，也不要额外给节点强写 0 字距。
- 当前导入仍为 `MIXED`/缺失、非目标值、类型/名称不符，或重新绑定造成真实排版冲突时，才进入下述默认值证据与探针路径。不能用“组件库已修复”的口头状态覆盖当前冲突，也不能修改组件库源文件绕过。
- 该路径同时适用于 PingFang SC 与 D-DIN；按各自发布 key 和真实字体属性核验，不把数字字体按中文字体规则处理。

#### 默认排版值的确认

- **未知字距默认 0，无需再次确认。** 本 Skill 已获得用户长期授权：没有读到明确字间距的区间，一律采用 `{unit:"PIXELS", value:0}`。适用于字距 `MIXED`、缺失或不可读，包含仍无法读取字距的发布样式；无需为此打开面板、索要截图、反复探测或暂停。只对尚未解析的字距采用默认值，明确非零字距和真实混合区间保持原值。该授权不适用于未知行高、字体、字号或其他属性，不修改发布库源文件。
- 对应文字/区间的 Figma 面板明确显示行高 `Auto`、字距 `0px` 时，即按默认排版理解；字距 `0%` 与 `0px` 等效。`Auto` 表示自动行高，不是 0px 行高。用户提供的当前面板截图也是有效证据，不要求代理必须重新截取同一面板。
- 用户已明确说明本次文字、同组文字或本页采用上述默认值时，按其确认的范围执行，记录原话或截图与适用节点；不重复索要确认。单节点确认不扩大其他属性的适用范围；未知字距则已由本 Skill 统一授权。面板空白、样式同名或 `MIXED` 不等于读出了 0，采用 0 的依据应如实写为本 Skill 默认规则。
- 采用本 Skill 默认字距且其他属性证据齐全后，核实目标发布 key、实际字体/字号及其余排版属性，继续正常批量联动；仅未知字距不触发临时探针或额外核验。确有下述独立触发条件时才验证操作顺序。即使节点或库源 API 字距仍返回 `MIXED`/缺失，也不继续把该项列为 `verification-pending`，不以此推断库损坏或要求先改发布库。正常检查中观察到明确非默认值、合法分段差异、字体错误或画面变化时，只处理实际冲突范围，默认规则不能覆盖这些差异。
- 将 API 原始返回值与采用的排版依据分开记录：例如 `rawApiLetterSpacing: "MIXED"`、`adoptedLetterSpacing: {unit:"PIXELS", value:0}`、`evidenceSource: "skill-default-zero-letter-spacing"`。面板或本次用户确认可分别记为 `editor-panel`、`user-confirmed-defaults`。不能声称 API 已读出 0。优先由等价发布样式承载零字距，应用后不追加重复赋值；确需显式设置时，仅处理未解析区间，并按下述流程验证，不为使 API 字段可读而重写其他属性。正式写入后的目标 key 和画面检查仍须独立完成。

只有其他必要属性仍未知、等价性尚未验证或实际冲突未解决时，才保留 `verification-pending`；已采用 0 的未知字距本身不计待核验或例外。没有独立探针触发条件时直接继续授权范围内的正式写入，不以默认字距为由再次停下；默认采用值本身也不代表链接和验收已经完成。

仅在其他必要排版属性仍未知、正常写入出现真实冲突，或确需显式修改已链接文字的字体、行高、字距、字体变量时，按以下流程处理；单纯将未知字距按 0 匹配不触发此流程：

1. 保存节点/区间、源属性、当前与目标发布 key、变量绑定、尺寸和截图。在已授权目标稿范围内创建独立临时副本，保留真实字体、混合区间、实例覆盖及布局上下文；不在交付节点上试错，不修改正式目标/共享母组件。先验证权限边界，不能用探针试写探测权限。
2. 在临时副本中验证完整操作顺序。对待诊断的候选先试用发布样式，回读真实字体、字号、行高、字距、样式 key，并核对编辑器与截图；未知字距按上节授权采用 0，其他修复仅针对已证实的差异。确需显式写入零字距时，先加载所需字体，仅设置未解析区间并检查链接与画面。`0%` 与 `0px` 都为零时无需为了单位统一重写属性；已绑定零字距样式后也不追加赋值。重新链接可能覆盖修复值，不能用“最后再套样式”代替验证。
3. 每次可能影响排版样式的写入后立即核对各受影响区间的目标发布 key。已记录的 key 非预期变空、改变或无法解析，记为 `link-regressed`，定位导致变化的操作；经核验的预期样式切换不算失链。只有修复后的真实属性与发布样式等价且探针通过时才恢复链接；否则回退本次未通过的操作。回退后也复核属性、绑定、链接和截图；如原有缺陷/等价性仍未解决，继续列待解决项。
4. 探针同时通过链接与排版检查后，将同一操作顺序用于交付节点，不能只在临时副本链接成功后就结束。对同一发布 key、字体/绑定模式及排版依据复用探针结果；模式、样式或行为改变时重验。用户补充默认值证据后，先复用仍适用的探针结果，继续完成此前已授权的修复。正式写入和组件派生后独立回读，不以探针结果替代最终审计；清理临时副本并返回创建/修改/删除 ID。

无等价样式、已证实不等价或已验证不可写的节点可带证据列合理例外；“工具读不清”和“本次操作失链未恢复”不能这样归类。若库属性与正确排版无法同时满足，只报告具体冲突和未完成状态，不反复改字距/重新套样式，不修改发布库、不创建近似本地样式凑联动率。少量必要覆盖也须分别记录真实链接状态和排版差异，不能冒算完全等价联动。

## 2. 正文 400 却偏细：核验真实字形，再定向修复

### 诊断

对独立 Text、母组件和有本地覆盖的实例文字共同记录：

- `fontName.family/style`、实际 `fontWeight`、字号、行高、字距、`textAutoResize`、文字边界及换行；混合字体用 `getStyledTextSegments()` 逐区间读。
- `textStyleId` 对应的发布 key 和真实属性；`boundVariables` 中字体相关绑定、变量 ID、当前模式解析值及本地覆盖。变量名称含 400 不等于实际解析值为 400。
- 实际 Paint/RGBA、文字和祖先透明度，排除同为 Regular 但颜色/透明度不同造成的视觉差异。
- 可用真实字体、`loadFontAsync()` 结果和 `hasMissingFont`；比较编辑器实际字体样式及同缩放截图。

CSS 400、API 返回 Regular、变量解析为 400，只能分别证明这些字段，不能单独证明最终渲染正常。`loadFontAsync()` 在本次调用后使 `hasMissingFont=false`，也不能证明编辑器持久状态已修好。未观察到 Light 时，不把原因写成“误用了 Light”。

### `hasMissingFont` 的终检顺序

每次 `use_figma` 调用都有独立的字体加载状态。在当前调用尚未加载节点实际字体时，`hasMissingFont=true` 可能只是运行时假阳性，不能直接计入最终缺失字体数量。最终字体回读必须在同一次调用内按以下顺序完成：

1. 遍历全部可见 Text；普通文字读取 `fontName`，混合文字用 `getStyledTextSegments()` 逐区间读取，并按 `family/style` 去重。
2. 对每个实际使用的唯一字体对执行并记录 `await figma.loadFontAsync()`；不可用字体已在 clone 上降级时，重新枚举降级后的真实字体对，不继续检查已放弃的原字体。
3. 全部实际字体加载完成后，再逐文字读取 `hasMissingFont`。加载前为 true、加载后为 false 的节点按“运行时尚未加载”记录，不算文件缺失，也不另发一次字体调用。
4. 字体对加载失败，或加载成功后节点仍为 `hasMissingFont=true` 时，返回节点 ID、文字区间和实际字体对，进入阻塞或证据冲突处理；不得把它静默改为 0。

这一顺序只消除读取时机造成的假阳性。最终仍须核对实际 `fontName`、字号、字重、行高、字距、文字边界和截图；`loadFontAsync()` 成功或 `hasMissingFont=false` 不能单独证明字形、排版或持久状态正确。

### 写入顺序

1. 保存受影响节点的真实字体、区间样式、发布 Style key、变量绑定及几何快照；当前调用中加载实际需要的字体，再修改 Text。
2. 若实际字体错误或别名字体不可用，优先应用已验证的真实目标字体。普通正文需要 Regular/400 时显式使用对应真实 Regular 字体；不要新建假字体别名，也不要改成 Medium/500 掩盖偏细。保留原有 Medium、Semibold、数字字体和混合文字区间。
3. 若字体字段正确但仍有渲染异常，检查旧的字体变量/实例覆盖。仅在受影响范围内尝试：记录可疑 `fontWeight` 绑定 → `setBoundVariable("fontWeight", null)` → 显式重设真实 `fontName` → 核对实际字重与截图。先在一个代表节点验证有效再批量处理；无效果则恢复绑定继续诊断，不对正常文字一律解绑。
4. 仅对已确认缺陷设置与字号、字体相符的行高；字距另按“默认排版值的确认”，未读到明确值时采用 0，已明确的非零值或分段差异保持。已有零字距发布样式不为消除 `MIXED`、统一单位或统一格式而重复赋值。确需修改时先按“文字样式链接保护”验证；需要显式行高时避免紧行高造成裁切。不要全局改字号或强制每种字体使用同一行高。
5. 同步授权范围内母组件、嵌套变体和仍保留旧覆盖的实例；只改母组件不足以证明实例已同步，须读回每个受影响节点。
6. 每步排版/变量写入后立即核对 Text Style key 与区间样式，发现失链按“文字样式链接保护”恢复或回退，不能等交付时才改记例外。所有 Style/变量写入完成后，独立回读并进行最终字体、几何和截图验收；恢复 key 后仍有错误字体/行高/字距同样不通过。必要的局部覆盖如实记录，不把有差异的覆盖计为完全等价联动。

**字体验收必须有两层证据**：独立于写入调用的最终属性回读；Figma 编辑器中每种受影响字体/绑定模式的代表节点实际样式面板与可见截图。均检查 family、style、字号、行高、字距，全部受影响节点另做属性审计。未知字距可直接采用本 Skill 默认 0；默认行高等仍须采用上节规定的用户确认或当前面板截图。代理截图失败不使已有有效证据失效。其余必要编辑器证据确实缺失时明确“尚未完成编辑器字体验证”，不得仅用调用内加载成功宣称完全修好。

对没有已授权替代方案的其他字体，若编辑器已确认可用字体及正确渲染，但工具仍报字体不可用/`hasMissingFont=true`，分开记录两侧证据与限制，按现有门槛判定；不反复加载同一失败字体，也不宣称接口缺失标志已消除。缺少编辑器证据或实际字形不正确时仍为未完成；不能把仅可加载的 Heavy/Medium 当作 Regular 的等价替代。宋体优先走下述已授权方案。

### 宋体必须使用思源宋体

用户已指定：宋体必须使用思源宋体，禁止降级为 `PingFang SC`。本规则适用于宋体/中文衬线文字，包含此类标题；黑体、无衬线标题仍按原字体体系和组件库规则处理。此要求优先于本 Skill 中通用的缺失字体降级规则。

先记录源节点/区间的真实字体名称和字重，再核验当前接口提供的思源宋体，优先使用 `Source Han Serif CN`。源稿的 `Source Han Serif SC` 名称无法加载时，可核验并采用 `Source Han Serif CN` 的相同字重；不能仅凭名称相似就认定完全等价，也不能把可加载的 Heavy/Medium 当作 Regular 的替代。原思源宋体名称与所需字重均可加载且字形正确时可保留，不为统一名称而重写。

只有真实可用的思源宋体字重与原字重一致时才进入授权目标稿写入。所需字重不存在或加载失败且无已验证的同字重思源宋体时，保留原稿并报告字体名称、字重及受影响节点；不得改用 PingFang、其他字体或错误字重，也不得把该阻塞改记为已通过的字体例外。相同环境复用已确认的加载结果，不反复加载同一失败字体；不自动安装字体或修改系统字体服务。

保持原字号、行高、字距、对齐及混合文字区间。写入前声明受影响文字和可能的排版位移区域；写入后核对真实思源宋体、字重、样式 key、尺寸、换行、基线和截图，区域外像素不变，区域内不得新增重叠或裁切。若字形确有变化，按限定区域字体修复验收，不声称仅名称不同就保证逐像素一致。

第二阶段及包含第二阶段的连续路径按实际排版属性匹配目标发布 Text Style：完全等价才链接；无等价样式时保留思源宋体，记录有证据的字体/排版例外，不为链接库样式改成 PingFang。第一阶段仍不绑定 Style；显式只执行第三阶段时保留现有 Text Style 和字体，只对组件化影响范围做前后保持验证，不主动改绑目标库样式。加载成功只证明当前接口可用，最终仍须通过独立字体回读及编辑器、几何和截图验证。

可复用案例：2026-09-17 接口核验中，源字体 `Source Han Serif SC / Heavy` 无法加载，而 `Source Han Serif CN / Heavy` 加载成功。这是相同字重的候选映射，不是其他字重可用或视觉等价的证明；后续任务仍按当前环境核验。

已验证示例：一组正文原本已报告 PingFang SC Regular/400，定向清除旧字重绑定并重设真实字体后，在编辑器确认 Regular、11px、16px 行高、0px 字距。11/16 只是该稿的规格；不能推广为所有正文尺寸，也不能据此推断所有 400 变量均有问题。

## 3. 同族数字/单位：在母组件上建立随内容增长的布局

### 缺陷识别

把“数值 + 分母 + 单位”或“数值 + 单位”视为同一逻辑行。分别读取各文本宽度和相对坐标，检查相邻文本框的实际间距。母组件存在、`mainComponent` 有效或外层尺寸相同，均不能证明这行正确。

例如原数值 43 宽 22，分母 x=23.53125；改成 108 后数值宽 30，分母仍在旧 x，产生约 6.47px 重叠。这不是内容不同所必需的差异，必须修复。不要用修改当前文案的 x、空格补位或把数字做成图片解决。

### 实现顺序

1. 先修正字体并加载所有真实字体；找到承担数量行职责的现有容器，在本地母组件上修复，避免给每个 Text 另建 Component 或无职责包装层。
2. 数量行设置为 `layoutMode="HORIZONTAL"`、`layoutWrap="NO_WRAP"`、`primaryAxisAlignItems="MIN"`、`counterAxisAlignItems="BASELINE"`，用一致的显式 `itemSpacing`；紧凑数字/单位默认可用 2px，已有可靠规范优先。
3. 文本使用 `layoutPositioning="AUTO"`、`textAutoResize="WIDTH_AND_HEIGHT"`，文字与数量行采用随内容增长的 HUG/AUTO 尺寸。检查并移除妨碍自适应的旧固定宽度、Absolute 和实例尺寸覆盖；保留确有对齐职责的外层固定槽位或最小宽度。
4. 不按数字位数硬写分母/单位的 x，不用负 gap，不把数字与中文单位按文本框顶部强行对齐。混合字体由 BASELINE 对齐负责；文字自然基线位置可以是小数。
5. 对同族所有状态统一共享的字体、行高、行内间距、内边距和对齐规则；只有真实状态/尺寸差异才允许不同。内容长度可以使 HUG 宽度变化，不要求不同数字的分母/单位保持同一个 x。
6. 母组件写入后，核对嵌套变体、预览及全部页面实例的实际布局；清理仍阻碍同步的局部覆盖。只设置了 Auto Layout 属性、但实际子项仍沿用固定位置，不算完成。

### 必须做内容长度回归

在临时实例中批量测试当前文案和短、中、长数字，覆盖位数增加及合理业务上限。未提供上限时，至少覆盖 1、2、3、4 位和最长现有文案；分母也要变长。测试后恢复原文案并删除全部临时节点，不保留测试副本。

每个样本返回实际文本内容、文字边界、行/槽位宽度、布局模式和相邻 gap；同一父级坐标下按 `next.x - (previous.x + previous.width)` 验证文本框间距与设定值一致。浮点计算误差只允许极小容差（如 0.001px），不能把 1.5px 四舍五入成 2px 后算通过。还要检查：

- 同族相同职责的行具有同样的 gap 和基线规则；不同字号/字体没有被压平。
- 没有负间距、文本框重叠、裁切、意外换行或溢出外层槽位；HUG 在文本变化后真实生效。
- 固定右侧槽位若有意保留，最长样本仍放得下。超出业务容量时报告或按已授权规则处理，不能靠压缩字距/缩小字体强行塞入。
- 原始页面文案、发布 Text Style key、颜色及组件血缘仍正确。

可复用的回归样例：`0/1`、`43/60`、`108/120`、`999/1000`、`9999/10000`，另对每种“数值 + 个”状态测试长数值。样例用于暴露固定坐标缺陷，不规定所有产品都必须支持相同最大值。

## 4. 间距规则覆盖现有组件内部

- 页面、母组件、变体和实例内现有与新增的显式 padding、gap/itemSpacing、行/列间距、段落间距均检查**整数偶数**，优先 4 的倍数；2px 适合紧凑数值行，6px 可用于原有紧凑布局。禁止“组件内部不检查”或“只检查本次新增间距”。
- 0px 是新建普通文字和未读到明确字距区间的默认采用值，无需再次确认。已有数据中的明确非零字距和真实分段差异保留，只有确认缺陷时才修复。百分比不能直接当 px，0% 不为统一单位改写为 0px；字距 MIXED 直接采用 0，不额外逐区间解析。因其他属性已取得区间数据时按区间保留明确值，其余采用 0；必要写入遵守“文字样式链接保护”，不全量清零。
- 同族组件的同一职责采用同一个间距值，不能每个实例各自四舍五入。可按整体布局把原 3/5/7px 归到 4/6/8px，但须同步校验容器、行高、换行和区域外位移，不把这个示例当通用映射表。
- 规则约束主动设置的间距；自然字宽、HUG 宽度、自动基线/居中产生的 x/y、字形轮廓留白和 SPACE_BETWEEN 自动分配的余量可以是奇数或小数。不要全局取整所有坐标和宽高，否则会再次破坏基线和内容自适应；本应固定 gap 的同族文字行也不能用 SPACE_BETWEEN 绕过一致性检查。
- 正确的发布样式/远程组件约束与本次间距规范冲突时，不修改发布库。先判断授权目标稿能否做必要的本地覆盖并保留血缘；不能安全覆盖则记录节点、属性和约束，明确未完成项，不能静默豁免整组组件。

## 5. 一次批量修复后的验收

1. 属性回读覆盖母组件、嵌套变体及全部受影响实例；确认字体、样式 key/必要覆盖、字色、布局、间距和文案。每次最终写入会使相关旧验证失效，尤其是重新应用 Text Style 后。
2. 字体的编辑器验证与数字长度回归通过；页面/组件内未处理的显式奇数或小数间距为 0，或有明确不能安全处理的例外。存在未解决的已确认缺陷时不得宣称全部通过。
3. 以相同节点、尺寸和导出参数比较：目标修复区域外差异为 0；区域内报告变化范围并目视确认正文、基线、间距和重叠已符合目标。无损组件抽取另用修复后的基线验证。
4. 所有实例仍可追溯到正确母组件，沿 lineage 验证发布样式 key 未意外丢失；`verification-pending`、`link-regressed` 均为 0 才能通过。即使截图一致、字体面板正确，也不能忽略未恢复的失链；样式 ID 非空但真实排版错误同样不通过。无隐藏母实例或覆盖层，临时节点全部清理，原文案恢复。
5. 返回修改/创建/删除 ID、关键属性前后值、回归样本及截图证据。字体探测、组件族盘点和数字样本尽量批量执行；失败、再次写入或证据失效才重验相应范围，不逐节点重复整页审计。

### 修改本流程时的回归案例

以“连对 × 2”（PingFang SC Medium 18，对应 H7_CN_Medium）和“继续 (5s)”（Medium 16，对应 Body1_CN_Medium）的失链案例验证行为；名称仅用于复现，执行时仍按当前发布 key/真实属性核验，不把两个样式永久列为异常。

| 输入/操作 | 应观察到的结果 |
| --- | --- |
| 用户说明组件库已修复/重新发布，按原 key 重新导入已明确返回目标字体、Auto 行高和 0% 字距 | 使旧 `MIXED`/旧版本结论失效；批量重新绑定正式节点，最后只做一次独立全量回读和一次视觉校验，不强写节点字距或重复探针 |
| API 字距返回 MIXED/缺失，当前对应面板明确显示 Auto 与 0px/0% | 接受已有证据并继续正常联动，不另建字距探针；正式 key 与画面通过后计入目标链接，不因 API 未变继续阻塞 |
| 用户明确确认本页 Auto 与 0px，已有同 key/字体/绑定模式的探针链接和画面通过 | 复用适用结果，完成正式写入；保留原始 MIXED 及用户确认记录，不重复要求确认或重建探针 |
| 样式或单字符区间字距仍返回 MIXED、缺失或不可读，没有面板或本次用户确认 | 直接采用 0，依据为 `skill-default-zero-letter-spacing`；不索要确认或仅因此暂停。继续匹配与正式写入，key 和画面通过后计入链接，不能仅凭采用值报完成 |
| 已有预检中大量字距未知，仅少量明确非零 | 复用预检：保留已知非零，其余直接采用 0；字距专用全量扫描、逐字符调用、面板检查和临时探针均为 0 次，正常联动和最终验收继续 |
| 节点汇总字距为 MIXED，区间分别明确为 0px、2px，另一区间不可读 | 保留前两段各自字距，仅对未知段采用 0，不压平区间 |
| 字距和行高均不可读 | 字距采用 0；行高仍单独核验，不将未知行高或 Auto 写成 0 |
| 节点字距不可读，但其源样式明确为非零值；或候选样式明确非零 | 保留已明确的源样式字距；候选非零值按真实属性比较，不能覆盖为默认 0 来伪造等价 |
| 用户确认默认值，但候选实际带来非零字距、错误字体、换行或尺寸变化 | 不按默认值放行；定位真实差异，恢复/回退未通过操作 |
| 经核验的样式为 0%，页面等效为 0px | 不为单位一致追加字距写入；真实排版与目标 key 同时通过 |
| 临时副本已链接，修改字体/字距后 key 变空 | 标记失链、定位并恢复/回退；失败操作不推广到交付稿 |
| 重新套样式保住 key，却带回错误字体/字距 | 验收失败，回退并报告冲突；不只检查 ID 或截图 |
| 全部属性与目标样式等价，组件派生后 key 仍正确 | 独立回读并检查截图后计为链接成功 |
| 源文字有明确且合法的多段排版，或库确无等价字号/字重 | 保留区间；能等价链接的区间正常链接，确无等价项据实列例外，不压平文字或强绑近似样式 |
