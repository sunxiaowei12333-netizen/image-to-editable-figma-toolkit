# 预设色键转真实 Alpha

仅当图片在首次生成/编辑前已经明确选择了与主体色域不重叠的单一高饱和色键、实际文件没有可用 Alpha，且该色键确实触达画布边界时读取本文件。生成器直接返回的合格 RGBA 透明 PNG 不走本流程；意外白底、棋盘格、渐变背景、原截图背景、色键进入主体、高光或半透明材质时也不得用本流程强行补救，应拒绝产物并按主 Skill 的重试规则处理。

## 输入门槛

处理前同时确认：

- 记录了生成时指定的精确色键 RGB/HEX，不从成图中猜色；
- 主体固有颜色、浅色高光、眼白、牙齿、皮肤、头发、服饰、道具和半透明区域均不使用该色键；
- 画布四周存在足够连续的色键背景，主体没有贴边截断；
- 保留未处理原图，输出写入新的 PNG 路径，不覆盖输入。

任一项不满足时停止。不要通过放大容差、全局 HSV 删色、连续腐蚀或涂黑主体边缘来追求“看起来透明”。

## 确定性处理

使用：

```bash
python3 scripts/extract_colorkey_alpha.py \
  /absolute/path/to/keyed-input.png \
  /absolute/path/to/output.png \
  --key '#FF00FF' \
  --qa-dir /absolute/path/to/qa
```

脚本执行以下受限处理：

1. 只以画布边界上的强色键像素为种子，在色键容差内做边界连通扩展；主体内部偶然接近色键、但没有与画布边界连通的区域不会自动删除。
2. 只在边界连通区域根据与色键的距离生成软 Alpha；主体不透明内部保持原 Alpha。
3. 只对新产生的半透明边缘执行 `composite = alpha × foreground + (1-alpha) × key` 的反合成去色；不透明主体 RGB 不变，不做全局调色。
4. 报告未与画布边界连通的近色键区域。默认只报告、不删除，避免把主体内部高光或固有颜色误当成镂空。

若报告存在 `enclosed_key_candidates`，逐项与原图和参考图核对。只有确认报告中的每一个候选都是真实镂空时，才允许重新运行并增加 `--include-enclosed-key-regions`；只要其中有主体固有颜色，就不得整批自动删除，应局部编辑蒙版或重新生成资源。

容差是当前文件的测量参数，不是跨任务固定值。默认值适合单一纯色键；若必须明显提高容差才能去掉背景，通常说明色键与主体重叠或背景不纯，应拒绝产物，而不是继续扩大阈值。

## 验收

脚本默认写出 JSON 报告；传入 `--qa-dir` 时同时生成 Alpha 蒙版、深色底、浅色底和棋盘格合成图。继续进入 HTML 前必须同时满足：

- 报告中的输出 `has_nonopaque_pixels=true` 且 `has_visible_pixels=true`；
- Alpha 可见边界完整，主体没有贴边截断；
- 深色和浅色底上没有色键毛边、白边、暗边或矩形底色；
- 头发、手指、眼白、牙齿、浅色高光、发光道具、服饰和半透明细节没有被挖空；
- `enclosed_key_candidates` 已逐项确认，新增透明岛均能对应来源中的真实镂空；
- 在最终显示尺寸的 `100%` 和 `200%` 下仍通过上述检查。

脚本报告和预览只提供可复核证据，不自动替代视觉判断。通过后再运行 `scripts/measure_alpha_bbox.py` 记录最终可见边界并反算 HTML 布局。
