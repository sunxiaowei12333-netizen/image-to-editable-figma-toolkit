# 预设色键转真实 Alpha

仅当直接真实 Alpha 不可靠、准备在首次生成/编辑前选择与主体色域强分离的单一高饱和色键，或需要把已按本规则生成的色键文件转换为真实 Alpha 时读取本文件。生成器直接返回的合格 RGBA 透明 PNG 不走本流程；意外白底、棋盘格、渐变背景、原截图背景、色键进入主体、高光或半透明材质时也不得用本流程强行补救，应拒绝产物并按主 Skill 的重试规则处理。

## 生成前选色

选色复用主 Skill 已有的参考图分析和视觉原子内部清单，不生成多张色键候选，也不增加新的图片重试条件：

1. 选择与主体色域差异最大的单一高饱和纯色；白、灰不作为常规色键。
2. 浅绿、白色或发光主体禁止使用白、灰、绿、青背景，默认使用已有成功记录的纯洋红 `#FF00FF`。
3. 其他主体逐项确认色键不会进入其不透明边缘、浅色/白色高光、发光区域、服饰、道具和半透明材质；存在任一重叠就换用更高对比色键。
4. 最终落点背景只用于提取后的实际页面合成 QA，不参与生成前色键排序或优先级，避免为了贴近页面颜色而选择容易污染主体边缘的键色。
5. 若没有安全色键，改用真实 alpha 或主 Skill 允许的其他合规图片方案，不得强行选择同色，也不得为了选色重新生成多张候选图。

在内部资源清单记录主体冲突检查、最终选定的精确色键和选择依据。后续提取以该记录值作为计划色，不得凭肉眼从任意像素猜测色键；生成器把计划纯色变成同一色族内的渐变、亮暗变化或统一色漂移时，由下述固定计划色族模型处理，不把实测任意边框色改当成新的计划色。

## 输入门槛

处理前同时确认：

- 记录了生成时指定的精确色键 RGB/HEX，不从成图中猜色；
- 主体固有颜色中的受保护边缘、浅色高光、眼白、牙齿、皮肤、头发、服饰、道具和半透明区域均不使用该精确色键或落入其提取容差；主体内部仅有同色系但色距安全的颜色不构成失败；
- 除明确构图需要的主体裁切边外，画布四周存在足够连续的计划色族背景；主体有意贴边或被画布裁切时，必须逐边记录并在命令中声明；
- 保留未处理原图，输出写入新的 PNG 路径，不覆盖输入。

任一项不满足时停止。不要通过放大容差、全局 HSV 删色、连续腐蚀或涂黑主体边缘来追求“看起来透明”。

## 确定性处理

使用：

```bash
python3 scripts/extract_colorkey_alpha.py \
  /absolute/path/to/keyed-input.png \
  /absolute/path/to/output.png \
  --key '#FF00FF' \
  --generated-key-input \
  --qa-dir /absolute/path/to/qa
```

上例 `#FF00FF` 对应浅绿、白色或发光主体的默认安全色；其他主体必须替换为该资源生成前记录、且与主体色域强分离的精确 HEX。`--generated-key-input` 用于图片生成器产出的计划色键文件；用户提供且来源明确的既有色键文件可省略该标记，并继续按实测参数处理。

若主体按参考图构图必须接触或裁切某条画布边，例如人物下半身在底边被裁切，追加 `--allow-subject-touch-edge bottom`；多条边重复传入。该参数只声明真实主体构图，不允许把色键残留、渐变背景或错误裁切伪装成主体触边。

## 生成色键边缘与计划色族审计

生成器产出的色键文件在分割前必须通过脚本的固定计划色族审计，并保持默认参数，不允许用自定义 `seed/grow` 放宽结果：

1. 分别统计上、右、下、左最外边的计划色族覆盖率，不能只看四个角、单一 RGB 距离或全图平均色。
2. 未声明主体裁切的边必须稳定属于生成前选定的计划色族；同一色族内的渐变、亮暗变化和统一色漂移可以进入自适应分割，不因最外边不接近一个固定 RGB 就拒绝。
3. 已声明的主体裁切边允许同时出现计划色族和真实主体；提取后只允许该边保留可见非键主体 Alpha。其他边的键色残留会被确定性清理，若仍存在非键可见像素触边，则以 `unapproved-subject-edge-contact` 拒绝，不能把它当成普通背景误差。
4. 任一未声明边由多个不兼容色簇、原截图背景或非计划色族主导，计划色进入主体受保护区域，必须手动放宽参数，或提取后深浅底/实际页面仍有可见键色残边时，脚本写出拒绝报告并停止。拒绝证据交回主 Skill 的统一重试门禁决定后续方法；本参考流程不得自行触发重新生成或继续腐蚀强行放行。

自适应色族分支只处理生成器对预先选定计划色做出的同色族变化；它不允许从意外白底、棋盘格、原截图背景或主体颜色中猜键，也不改变生成前的候选色安全判断。

脚本执行以下受限处理：

1. 由计划色的色相、饱和度、亮度和色度方向建立固定色族，只以画布边界上的强计划色族像素为背景种子；不会根据成图任意猜键。
2. 对边界连通的计划色族和局部背景模型生成软 Alpha；主体内部偶然接近色键、但没有与画布边界连通的区域默认不删除。
3. 将干净主体内部 RGB 受限延展到新产生的软边，并只在窄轮廓内抑制计划键色残留；不做全局调色、连续腐蚀或主体内部涂黑。
4. 报告未与画布边界连通的计划色族候选。默认只报告、不删除，避免把主体内部高光或固有颜色误当成镂空。

若报告存在 `enclosed_key_candidates`，使用 QA 目录自动生成的 `enclosed-candidates-marked.png` 与 `enclosed-candidates-contact-sheet.png`，逐项与原图和参考图核对。只有确认报告中的每一个候选都是真实镂空时，才允许重新运行并增加 `--include-enclosed-key-regions`；只要其中有主体固有颜色，就不得整批自动删除，应局部编辑蒙版或重新生成资源。

用户提供的既有色键文件中，容差仍是当前文件的测量参数，不是跨任务固定值。生成器产出的计划色键文件必须走 `--generated-key-input`，不得覆盖默认参数；同色族渐变和色漂移由固定自适应模型解决。若仍必须提高容差才能去掉背景，说明色键与主体重叠或背景不兼容，必须拒绝产物，而不是继续扩大阈值。

## 验收

脚本默认写出 JSON 报告；传入 `--qa-dir` 时同时生成 Alpha 蒙版、深色底、浅色底和棋盘格合成图。继续进入 HTML 前必须同时满足：

- 报告中的输出 `has_nonopaque_pixels=true` 且 `has_visible_pixels=true`；
- Alpha 可见边界完整；只有命令中明确声明且与参考构图一致的边允许主体贴边或被画布裁切；
- 深色底和浅色底上没有色键毛边、白边、暗边或矩形底色；
- 头发、手指、眼白、牙齿、浅色高光、发光道具、服饰和半透明细节没有被挖空；
- `enclosed_key_candidates` 已逐项确认，新增透明岛均能对应来源中的真实镂空；
- 在最终显示尺寸的 `100%` 和 `200%` 下仍通过上述检查。

进入 HTML 后复用既有综合预览，把元素放在最终局部背景上再次检查同一组边缘问题；不新增色键专用页面或图片生成调用。实际背景仍有可见色边时必须在进入 Figma 前修正，不能因为深浅底已通过而放行。

脚本报告和预览只提供可复核证据，不自动替代视觉判断。通过后再运行 `scripts/measure_alpha_bbox.py` 记录最终可见边界并反算 HTML 布局。
