# 异常处理

仅在对应异常发生时使用本文件；找到匹配项后执行其处理要求，不要因为正常路径尚未结束而预先执行异常分支。

- **尺寸判断不确定**：如果用户已明确要求 Pad/平板、手机横屏或手机竖屏，即使原图宽高比不匹配，也按用户要求分别采用 `1024 × 640`、`812 × 375` 或 `375 × 812`，并记录“用户设备类型/方向要求优先”的依据；只有用户未指定设备类型/方向时，才报告原图尺寸、计算后的宽高比，以及它与三种标准画布比例的差异并按最接近的宽高比归类。仅当用户未指定且比例没有明显匹配、画面形态接近 Pad 时，才采用 Pad `1024 × 640`。不得仅凭“大尺寸”或“高分辨率”判定为 Pad。
- **HTML 不存在或路径错误**：停止采集，检查绝对路径和中文 URL 编码；必要时启动本地服务器后重试。
- **候选 HTML、目录或资源已存在**：视为命名冲突，不得覆盖、删除或清空；为当前任务生成新的短 ID，或在同一任务内递增到下一个不存在的版本目录，再更新 HTML、资源和预览 URL。用户未明确授权时，现有文件一律按其他任务或历史版本保护。
- **旧 HTML 链接显示了新任务内容**：停止采集与交付，检查是否覆盖了同名 HTML/资源、复用了可变软链接，或用同一 `端口 + URL 路径` 启动了不同服务器根目录。恢复为唯一任务/版本目录与唯一 URL；不能确认旧文件内容时不得擅自重建或覆盖，应保留现状并报告受影响的精确路径。
- **页面内容缺失**：检查异步资源、图片路径和字体加载；官方通道同时检查 `capture.js`，等待页面稳定后使用新的 Capture ID 重采集；本机字体通道从同一唯一 HTTP URL 重新运行既有插件，不创建 Capture ID。
- **发布组件名称或语义正确但视觉样式不一致**：拒绝该候选，不得因它来自设计系统就接受错误的描边/面性、方向、笔画、颜色、外壳、材质或状态。对明显定制且视觉权重高的复合控件，在原有检索中改用“控件职责 + 状态”寻找精确 Variant；普通图标改用视觉更接近的 Hugeicons 主组件并以 `Instance` 交付。不得把库 SVG 作为页面层级中的普通 Vector 或无职责 Frame；只有现有最终截图仍无法判断时才追加局部对比。
- **预览或 Figma 文字明显偏粗**：检查 CSS 是否使用 `bold`、`<b>`/`<strong>` 默认样式、请求了不存在的字重，或字体是否未加载并触发回退；再核对浏览器 computed style 与 Figma 文本节点。正文先恢复为 `400`，按钮/控件先恢复为 `500`，标题证据不明时使用 `500`；仅在同字体样本对照后才提高到 `600`，不得直接设为 `700` 掩盖字体族或渲染差异。
- **预览或 Figma 某个文本块明显偏细**：不要按“正文默认 `400`”继续接受，也不要把整页正文统一加粗。使用现有综合截图在相同显示比例下只比较该文本块同字体的 `400/500`，确认字体均真实可用后局部修正，并复核字宽、换行和基线；只有现有截图无法判断时才增加局部对比。
- **Figma 双击文字后字形、字宽或换行发生变化**：说明导入节点可能仍保留浏览器旧文字盒、替代字体预览或临时绑定；面板字体名、`lineHeight=AUTO` 和 `hasMissingFont=false` 均不能单独排除。若当前 Figma 执行环境能加载与 HTML 同源/同版本的目标字体，按 [figma-normalization.md](figma-normalization.md) 先测量临时 fresh Text；fresh Text 正确而导入 Text 不稳定时，用全新的原生 Text 受控替换，保持真实字体、Auto 行高、源设计实际字距和视觉锚点，不给旧节点补固定行高或负字距。混排 Text 必须先保存并逐 range 恢复样式，禁止整段同内容回写测试。若字体只在用户本机浏览器/Figma 可用，不得用缺字的无头环境重排，改由已授权的本机导入/桌面环境修复。若用户实际 Figma 也不可用，自动替换为近似字体后再验收；不得把“未双击时看起来正确”作为交付依据。
- **HTML 与用户手动插件导入正确，但官方自动导入或自动规范化后的字体错误**：先比较字体 family/style/source 与代表文本的 DOM/Capture/fresh Figma 三阶段指纹，确认问题是字体隔离、旧文字盒或临时绑定，而不是字号或行高。当前 Figma 执行环境能加载同源字体时，优先在本次官方 Capture 子树内执行 fresh Text 受控替换；不能加载同源字体时才删除或舍弃当前错误节点，使用已授权的本机 Chrome/Figma 插件从当前唯一 HTTP URL 重新导入一次。不要用改字号、字距、固定行高或替代字重掩盖；历史节点和旧 HTML 不得触碰。重新导入后，对不能在当前环境安全加载的字体只做只读审计。
- **文字排版属性或文本层出现小数**：先确认小数属于可控设计属性，而不是字体引擎内部字形度量。检查高分辨率换算、祖先 `transform: scale(...)`、非整数 `zoom`、`rem/em`、百分比/无单位行高和 Capture 转换；移除缩放，在最终画布上将字号、像素行高、默认字距及文本层可控几何值重设为经参考图对比选出的整数。不要未经视觉对比批量四舍五入，也不要为消除内部字形度量而破坏排版。
- **采集尺寸错误**：检查根容器、viewport、浏览器窗口和 CSS media query，修正后重新采集并验证 metadata。
- **采集了错误页面**：停止流程，核对地址栏和文件内容，删除错误 Figma 节点后从正确 HTML 重新开始。
- **Capture 序列化载荷有超过 50 MB 的风险**：不要压缩、降采样或改透明边缘，也不要因此改用浏览器插件。必须在 HTML 审批前根据构建结果的 `officialPayloadRisk` 将唯一 Capture HTML 重建为 `--asset-mode external`，只把同一版本目录、同一校验值的原图和字体改为相对 HTTP URL；重新完成 HTTP 预检、构图、字体度量和预览截图后再请求审批。若风险是在审批后或提交时才被证实，文件指纹已经变化，必须重新经过 HTML 审批门。
- **Capture 状态长期 pending**：若连续 2 次约 5 秒轮询仍为 `pending` 且没有提交迹象，立即检查独立 Chrome 是否位于前台、`document.visibilityState/hidden`、一次 `requestAnimationFrame` 是否能回调、最终 URL 是否执行了完整 reload、`capture.js` 与 hash 中的 `captureId`/endpoint 是否正确、字体/图片是否加载、External 资源是否返回成功、隔离 Chrome 进程是否仍在运行。条件修复前不继续机械轮询；未提交的 ID 可继续使用，已提交或消费的 ID 不可复用。只有页面已提交或处于 `processing` 时才继续最多约 10 次轮询，不得随意切换方式。
- **Capture ID 已消费或返回 409**：该 ID 不可复用。若 Figma 中已有正确结果，直接验证该节点；若需重采集，生成新的 Capture ID 并只提交一次。
- **专用 Chrome profile 尚未初始化**：创建空白的长期专用 profile并直接用于官方脚本采集；默认无需登录 Figma、安装扩展或人工确认。
- **专用 Chrome profile 损坏**：不得自动删除 profile、复制日常 Chrome 数据或绕过安全提示；先报告具体状态，由用户确认后重建专用 profile。
- **Figma 官方 Capture 工具不可用**：明确报告阻塞点和已完成的 HTML/预览，不输出虚假节点链接。只有用户确认后才改用 Chrome 扩展备用路径；安装时仅使用官方来源并由用户完成权限确认。
- **目标 Figma 文件无权访问**：不要改用其他文件；检查 Figma MCP 身份与文件权限，并请求用户授权或提供可访问链接。
- **未提供 Figma 链接**：先告知用户将创建新文件；按 `figma-create-new-file` skill 创建并验证新文件，再按字体预检选择官方 Capture ID 或本机字体导入通道。
- **用户提供的 Figma 链接无权限或失效**：不要自动改用其他文件；报告链接访问失败，并请求用户提供可访问链接或授权。
- **视觉不一致**：以整体构图和组件级细节为优先重新调整 HTML；不要仅通过缩放截图、铺设合成参考图或增加遮罩掩盖布局问题。
- **透明 PNG 外框正确但主体显小、显大或偏位**：测量 alpha bounding box，比较参考图与预览图中的可见主体边界；按透明留白反算 `<img>` 的宽高与 `left/top`。不得继续调整 DOM 外框数字来碰运气，也不得仅依据 Figma 节点 metadata 宣称比例正确。
- **透明 PNG 出现矩形底色、白边、暗边或可疑光晕**：仅在该异常发生时，将同一资源临时放到白色、黑色和棋盘格底上检查 alpha 边缘与底色污染；修复或重新生成资源后再回到现有综合截图验收。正常透明资源不得为此增加默认对照板、截图或 Capture。
- **完整物体缺少内部结构或固定文字**：先确认其属于视觉原子内部，而非动态 UI；重新生成或编辑完整图片，补齐封面印刷文字、书脊、页芯、后封露边、厚度等缺失内容。不得用独立 HTML/Figma 文本或形状临时覆盖图片缺陷。
- **固定图片文字与 UI 文字边界不确定**：若文字印刷/绘制在物体表面并随物体透视、材质、缩放一起变化，默认并入图片；若文字承担页面信息、需要更新/交互/本地化/数据绑定，则拆成独立文本。仍不确定时根据用户要求确定并记录理由。
- **完整 IP 被拆成大量矢量或子图层**：停止交付。除非用户明确要求编辑角色内部结构，否则将角色本体、服饰、表情、道具和固有光影重新合并为一张独立透明图片；风格扁平不能作为继续拆分的理由。移除仅用于组织这些内部部件的 Frame/Group，也不要为纯装饰 IP 添加点击热区。
- **复杂画框或礼物被过度矢量化**：判断其是否包含密集不规则部件、复杂材质、纹理、高光、阴影或手绘边缘，且内部是否存在实际编辑需求。若复杂且内部无需编辑，将框体或礼物本体重新交付为一个透明图片图层；画框内 UI、动态促销标签和明确的交互控件保持独立，不得随图片合并。
- **图片对象是否可点击不确定**：先检查参考页面是否存在按钮样式、悬停/按下状态、跳转含义或其他交互证据。没有证据且用户未要求时按纯装饰处理，不创建事件、Prototype 或透明命中 Frame；有明确交互时仅增加承担命中职责的独立透明容器，不拆分图片内部结构。
- **反馈截图带红框或箭头**：把标记终点视为问题定位信息，检查其指向区域；除非用户明确要求，不得把红框、箭头或批注文字作为设计元素生成。
- **参考图被整体复用或前景未拆分**：停止采集，移除合成截图/含相邻内容的裁切前景，保留或重建纯背景层；按视觉原子规则分别生成简单前景 SVG 和完整视觉原子透明 PNG。通过资源隔离检查后才能继续。
- **背景被采集为 Frame fill**：停止交付，将背景从 CSS `background-image`、容器填充或合成截图中移除；改为根画布内最低层的独立 `<img>` 节点，重新完成本地预览、采集与 Figma 图层验证。
- **图片外面存在无职责包装 Frame/Group**：停止交付。若包装层只含一个同尺寸图片子节点，将图片提升到包装层父级，保持其绝对位置、尺寸、旋转、透明度和层级后删除包装层；若叶子 Frame 本身只有 `IMAGE` fill，则重建为直接叶子 Rectangle 图片图层。只有裁切、Mask、Auto Layout、响应式、滚动或交互职责经过验证时才保留外层节点。
- **背景以上仍存在纯样式 Frame**：停止交付，先区分它是 CSS 盒模型残留还是必要容器；前者按几何重建为 Rectangle/Ellipse/Vector，纯视觉集合改为 Group，后者将可见底板拆成独立 Shape 并记录容器职责。嵌套 Frame 无法 Flatten 时使用显式路径或原生形状，不反复调用 Flatten。
- **插入 Shape 后 Auto Layout 尺寸改变**：先检查父 Frame 的 `layoutMode`、sizing 和子节点 positioning；装饰层在必要的 Auto Layout 内设为绝对定位，不需要 Auto Layout 的容器恢复 `layoutMode = "NONE"` 和原始宽高，再截图验证。
