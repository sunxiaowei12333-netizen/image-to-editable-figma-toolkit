# HTML 阶段的基础规范（测试版）

## 范围和来源

只在 HTML 编写过程中设置字体、字重、字号、字色、图标色、自动行高、默认零字距，以及原生绘制层的透明度。按钮尺寸、形状和圆角按参考图还原，不执行完整 `editable-design-basic-standards` 第一阶段，不绑定 Figma 发布 Text/Paint Style，不为基础规范另建页面或组件。Figma 导入后仍须保留原 Skill 的真实字体、布局、节点语义审计。

本文件是可独立使用的静态快照，不依赖原版 Skill 的相对路径。普通测试直接读本文件，不再次访问规范链接。仅用户要求更新规范，或提供明确的新版本/冲突证据时，才按范围刷新快照；当前任务里不修改原版 Skill。颜色数值不代表已链接到 Figma 发布样式。

## 字体与排版

- 中文无衬线默认 `PingFang SC`。宋体/中文衬线风格必须用真实可加载、匹配字重的 `Source Han Serif CN`（思源宋体），不要改成苹方；所需字重不可用时报告缺失，不伪粗体、不改用其他字重凑成功。
- 具有真实笔写证据的中文按主 Skill 使用 `YRDZST`，圆润黑体不当成手写体；数字字体按主 Skill 的 `D-DIN` 规则。每种实际使用的 family/weight 仍检查加载与度量一次。
- 中文字号表为 `12, 13, 14, 16, 18, 20, 24, 28, 32px`，按最终画布的语义层级和参考大小选相邻候选，优先偶数；`13px` 是真实规范中的小字档，不是把所有字号强制偶数。D-DIN 规范字号为 `14, 16, 18, 20, 24, 28, 36px`。思源宋体等非库字体沿用合适字号档，不为套库改变字形风格。明显超出范围的大型展示标题先保留合理层级并记录例外，不机械压到 32px。
- 字重依视觉证据；正文通常 400，控件通常 500，具体可用字重和例外遵循主 Skill。不因为库某个字号默认 Semibold 就把全页强制加粗。
- HTML `line-height: normal; letter-spacing: 0px`。用户明确指定的特殊排版优先。Figma 中在字体安全加载、可安全重排的前提下使用 Auto 行高和零字距；不得靠固定行高、缩放或伪粗体掩盖字体差异。

## 文字和图标如何选色

颜色匹配使用 `scripts/match_standard_color.py` 的 `policyVersion: 2`。所有文字和 UI 图标都参与匹配；相差明显时保留原色。色系只用于选择候选，不能单凭同属橙色、黄色等就替换，也不再用 `ΔE00 > 5` 一票否决。

1. **合并现有分析，不增加处理轮次**：在第一次参考图分析中，估计文字/图标实心内部的代表色与落点背景色，避开阴影、描边和抗锯齿。已有清晰像素样本时可直接复用；目测估计需注明不确定性，不能写成精确吸色。普通交付不为颜色另加逐块采样、全图扫描、图片模型、截图、浏览器会话或单独审色轮次；看不清或混合效果无法确定时保留原色，不反复追色。
2. **同色且同用途去重后一次计算**：在现有批量资源准备中运行 `python3 scripts/match_standard_color.py <HEX> --background <当前落点背景代表色>`。不要因某候选被拒绝再调用一次；脚本会在同次计算中筛选其他候选。不同文字用途、背景或混合字色不能直接复用一条决定。
3. **黑白灰和彩色分别匹配**：
   - 近黑：RGB 最大通道不超过 51，通道差不超过 8，默认候选 `#333333`。这包括轻微偏暖的近黑；明显棕色、深蓝不能按黑色处理。近黑统一是用户明确要求，允许这个窄范围内到 `#333333` 的明度调整；不被通用明度差或相对对比度降幅限制拦回，但仍执行下述绝对可读性底线。
   - 已有规范色保持原规范色，近黑默认规则优先于 `#222222` 的精确命中。
   - 灰色：Lab 色度 `C* ≤ 6` 时，使用上表**全部 8 个灰阶及白色端点**，先排除不合适候选，再按明度差选择；最近灰阶未通过保护时继续比较其他灰阶。
   - 近白：其余颜色中 `L* ≥ 90 且 C* ≤ 14` 的低彩度亮色可候选白色；灰阶及已有规范浅色优先保留其相应层级，米棕正文不会仅因偏浅就改白。
   - 彩色：按源色相选取色板中的红、橙、黄、绿、蓝及其衍生色，再按下述边界筛选。同色系可包含多个候选；青、紫等没有专属规范色时保留，不强行跨色系。不得按文案、位置或“强调文字”直接指定品牌橙。
4. **候选必须满足实际差异边界**：当前正式版使用 `ΔE00 ≤ 15`、`|ΔL*| ≤ 12`、`|ΔC*| ≤ 40`；近黑默认分支不适用明度差 12 的限制；彩色同系候选另需 Lab 色相角差 `≤ 15°`。脚本负责一致执行，不在每张图临时放宽阈值。这些是设计匹配边界，不代表两色肉眼相同，也不代表已验证所有图片。
5. **保护实际背景上的可读性**：已有背景代表色时，除近黑默认分支外，候选对比度至少保留原值的 75%；原值达到 4.5 时替换后不得低于 4.5。原值不足 4.5 的一般匹配仍受 75% 降幅界限约束；近黑默认分支则不得进一步降低已有低对比。这是本 Skill 的候选保护规则，不是整页可访问性认证。没有候选同时满足差异与背景条件时保留原色；不要为了命中规范而提亮全部正文或丢失主次。沿用最终画布 `100%` 验收，顺带查看替换过的文字是否过亮、变色或抢眼；明显不适合时否决替换，记录原因，不增加独立复核轮次。
6. **用户指定与自动匹配分开记录**：明确指定的色值标记 `user-specified`；“看起来更接近某色”用于核对，不能冒充用户指定 HEX。用户讨论过的例子只作回归样例，不把特定文案、位置或上一张图的覆盖写死。
7. **在既有记录中覆盖实际用色**：`color-decisions.json` 至少保存 `role / referenceEstimate / targetHex / method / reason / deltaE00`，并保留脚本的 `policyVersion / matchedStandard / decisionFamily / lightnessDelta / chromaDelta / hueDelta / contrastGuard`。`nearestStandard` 是全色板数值最近项，**实际选中值以 `targetHex` 与 `matchedStandard` 为准**，不能误用已被保护条件拒绝的最近项。每处文字/图标的用色都应对应一条决定；没有匹配依据的直接 HEX 不算已执行规范。方法继续使用 `user-specified / closest-standard / reference-preserved / background-preserved`，其中 `closest-standard` 指合格候选内的匹配。

## 背景和装饰例外

背景色替换后若明显改变原图的明度、色温、材质或整体气氛，保留参考色/渐变，记录 `background-preserved`；例如米棕底不强制套浅橙底。位图内固有颜色不逐像素映射色板。文字/icon 是否保留原色按上一节的分类、候选差异与背景保护条件决定，并记录为 `reference-preserved`，不借用背景例外。

## 透明度

原生可编辑的 Fill/Stroke/阴影/必要节点透明度使用就近偶数整数百分比，例如 `9.4% → 10%`、`33.33% → 34%`。临界值以较接近且合成效果正常的候选为准，范围 0–100；不把接近 0 的必要可见细线舍成不可见。CSS 使用明确 alpha（如 `rgba(255,255,255,0.10)`），避免 `#FFFFFF18` 产生 24/255≈9.4% 的值。只调整底板时不得给父容器加 opacity 而连带影响文字。

**不量化位图的 Alpha、毛发、抗锯齿、发光或半透明纹理的逐像素透明度**，也不量化浏览器栅格化产生的边缘像素。透明度数值检查和视觉对照合并进已有 HTML/最终预览，不新增单独轮次。
